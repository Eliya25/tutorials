1. מבוא: מה זה JavaScript

JavaScript היא שפת התכנות של ה-web — היחידה שרצה באופן טבעי בכל דפדפן, ובזכות Node גם בשרת. היא הבסיס ל-TypeScript (superset שלה) ולכל האקוסיסטם שלמדת.

הטבע של השפה — ארבעה מאפיינים

  • Dynamically typed — הטיפוס נקבע בזמן ריצה, לא מוצהר מראש. משתנה יכול להחזיק string ואז number. (זה מה ש-TypeScript בא לרסן).
  • Weakly typed — JS ממירה טיפוסים אוטומטית (coercion) — מקור לכוח וגם ל-quirks (פרק 4).
  • Multi-paradigm — תומכת ב-imperative, functional, ו-object-oriented. אתה בוחר סגנון.
  • Prototype-based — ה-OOP שלה מבוסס prototypes, לא classes אמיתיים (פרק 10) — גם אם התחביר של class מסתיר את זה.

ES — גרסאות השפה

JavaScript מתוקננת כ-ECMAScript (ES). הקפיצה הגדולה הייתה ES6 (ES2015) — שהוסיפה let/const, arrow functions, classes, promises, destructuring, ועוד. מאז יש עדכון שנתי (ES2016, ES2017...). כשאומרים "JS מודרני" מתכוונים ל-ES6+. המדריך הזה מודרני לחלוטין.

הקשר לסדרה: כיסינו את הטיפוסים במדריך TypeScript ואת ה-runtime (event loop, streams) במדריך Node. כאן המיקוד הוא מכניקת השפה — איך JS מתנהגת ולמה. אזכיר את השניים ואפנה, בלי לחזור. אם משהו כאן על async מרגיש חסר — ההשלמה במדריך Node.

2. משתנים — var, let, const, Hoisting, TDZ

שלוש דרכים להצהיר משתנה, וההבדלים ביניהן הם מקור נפוץ לבאגים. חובה להבין לעומק.

const, let, var

const PI = 3.14;      // לא ניתן להשמה מחדש. ברירת המחדל שלך.
let count = 0;        // ניתן להשמה מחדש. כשצריך לשנות.
var old = "avoid";    // הישן — הימנע ממנו (הסבר למטה)

ההבדל הקריטי: Block Scope מול Function Scope

  • let/const — block-scoped: קיימים רק בתוך ה-{} שבו הוגדרו (if, for, בלוק).
  • var — function-scoped: מתעלם מבלוקים, קיים בכל הפונקציה. זה מקור באגים.
if (true) {
  let x = 1;
  var y = 2;
}
console.log(y);   // 2 — var "דלף" מחוץ לבלוק!
console.log(x);   // ❌ ReferenceError — let נשאר בבלוק (נכון)

Hoisting — "הרמה"

JavaScript "מרימה" הצהרות לראש ה-scope לפני ההרצה. אבל ההתנהגות שונה בין הסוגים, וזה מבלבל:

console.log(a);   // undefined — var "מורם" אבל בלי הערך
var a = 5;

console.log(b);   // ❌ ReferenceError — let מורם אבל ב-"TDZ"
let b = 5;

TDZ — Temporal Dead Zone

let ו-const כן "מורמים", אבל נמצאים בTemporal Dead Zone — אזור בין תחילת ה-scope להצהרה, שבו הגישה אליהם זורקת ReferenceError. זה בכוונה — כדי לתפוס באגים של שימוש-לפני-הצהרה (בניגוד ל-var שמחזיר undefined מבלבל). זו עוד סיבה להעדיף let/const: הם מכריחים אותך להצהיר לפני שימוש.

הכלל המעשי

השתמש ב-const כברירת מחדל, let כשצריך לשנות, ו-var אף פעם. const ראשון מבהיר כוונה (הערך לא ישתנה) ומונע באגים. עבור ל-let רק כשאתה באמת מבצע reassignment. var הוא שריד מלפני ES6 — אין סיבה להשתמש בו בקוד מודרני.

הערה על const עם objects: const מונע reassignment של המשתנה, לא mutation של התוכן. const arr = [] — אי אפשר arr = [...], אבל arr.push(1) מותר (התוכן משתנה, המשתנה עדיין מצביע לאותו מערך).

3. טיפוסי נתונים — Primitives מול Objects

ב-JavaScript יש שתי קטגוריות-על: primitives (ערכים פשוטים) ו-objects (הכל השאר). ההבחנה קובעת התנהגות מהותית — במיוחד השמה והשוואה.

שבעת ה-Primitives

טיפוסדוגמה
string"hello"
number42, 3.14 (אין int/float נפרד)
bigint100n (מספרים ענקיים)
booleantrue / false
undefinedמשתנה בלי ערך
null"אין ערך" מכוון
symbolמזהה ייחודי (פרק 18)

כל השאר — arrays, functions, dates, {} — הם objects.

ההבדל המהותי: Value מול Reference

זו אחת ההבחנות החשובות ב-JS. באופן מדויק, JavaScript תמיד מעבירה ערך. במקרה של primitive הערך הוא המספר/המחרוזת עצמם; במקרה של object הערך הוא reference לאובייקט. לכן העתקת משתנה של object מעתיקה את ה-reference, ושני המשתנים מגיעים לאותו object:

// Primitives — עותק:
let a = 5;
let b = a;      // b מקבל עותק
b = 10;
console.log(a); // 5 — a לא הושפע

// Objects — reference:
let obj1 = { x: 1 };
let obj2 = obj1;   // obj2 מצביע לאותו object!
obj2.x = 99;
console.log(obj1.x); // 99 — שניהם אותו object!

זו הסיבה ש"שיניתי עותק ופתאום המקור השתנה" — לא היה עותק, היה reference. כדי להעתיק object צריך במפורש: {...obj} (shallow) או deep clone.

typeof — בדיקת טיפוס

typeof "hi"        // "string"
typeof 42          // "number"
typeof true        // "boolean"
typeof undefined   // "undefined"
typeof {}          // "object"
typeof []          // "object"  ⚠️ מערך הוא object!
typeof function(){}// "function"
typeof null        // "object"  🐛 באג היסטורי מפורסם ב-JS!

שים לב לשתי מלכודות: typeof null === "object" (באג ידוע שנשאר לתאימות), ו-typeof [] גם "object". לזיהוי מערך: Array.isArray(x).

4. Type Coercion ו-Equality — ה-quirks

זה הפרק ש-JavaScript מפורסמת (לשמצה) בזכותו. ההמרות האוטומטיות של JS יוצרות התנהגות מפתיעה — והבנתן היא ההבדל בין לפחד מ-JS לשלוט בה.

== מול === — ההבחנה הכי חשובה

=== (strict equality) משווה בלי המרה — טיפוס וערך חייבים להתאים. == (loose equality) ממיר טיפוסים לפני ההשוואה, מה שיוצר תוצאות מטורפות. הכלל: השתמש תמיד ב-===.

5 === "5"     // false — טיפוסים שונים
5 == "5"      // true  — == ממיר את "5" ל-5

0 == false    // true  — coercion
"" == false   // true
null == undefined  // true
[] == false   // true  🤯
[] == ![]     // true  🤯🤯 (הדוגמה המפורסמת לטירוף של ==)

שים לב כמה == מסוכן. === תמיד צפוי. היוצא מן הכלל היחיד ש-== שימושי: x == null בודק גם null וגם undefined בבת אחת — אבל גם זה עדיף במפורש.

Truthy ו-Falsy

בהקשר בוליאני (if, &&, ||), JS ממיר ערכים ל-true/false. יש בדיוק שמונה ערכים falsy, וכל השאר truthy:

// כל ה-falsy values (שווה לזכור בעל-פה):
false, 0, -0, 0n, "", null, undefined, NaN

// כל השאר truthy — כולל מלכודות:
if ("0") { }        // truthy! string לא-ריק
if ([]) { }         // truthy! מערך ריק
if ({}) { }         // truthy! object ריק
if (" ") { }        // truthy! רווח

המלכודות: "0", [], {} כולם truthy. זו הסיבה שבדיקת "מערך ריק" עם if (arr) תמיד true — צריך if (arr.length).

coercion בפעולות

"5" + 3     // "53"  — + עם string = concatenation
"5" - 3     // 2     — - ממיר ל-number
"5" * "2"   // 10    — * ממיר
5 + null    // 5     — null → 0
5 + undefined // NaN — undefined → NaN
"abc" * 2   // NaN

NaN — הערך המוזר

NaN ("Not a Number") הוא הערך היחיד ב-JS שלא שווה לעצמו: NaN === NaN הוא false. לבדיקה משתמשים ב-Number.isNaN(x). הוא נוצר מפעולות מתמטיות לא-חוקיות ("abc" * 2, 0/0).

המספרים הצפים — floating point

0.1 + 0.2 === 0.3   // false! 🐛
0.1 + 0.2           // 0.30000000000000004

זו לא בעיה של JS אלא של ייצוג floating point (IEEE 754) בכל השפות. הלקח (חוזר ממדריך SQL): אל תשתמש ב-floats לכסף. עבוד ב-cents (integers) או ספרייה כמו decimal.js.

5. אופרטורים

אריתמטיים ולוגיים

+ - * / % **        // ** = חזקה (2 ** 3 = 8)
&& || !             // AND, OR, NOT
=== !== < > <= >=   // השוואה (תמיד === לא ==)

Short-circuit — התנהגות חשובה של && ו-||

&& ו-|| לא מחזירים בוליאני אלא אחד מהאופרנדים, ועוצרים מוקדם:

a && b   // אם a falsy → מחזיר a, אחרת b   (מחזיר את הראשון ה-falsy או האחרון)
a || b   // אם a truthy → מחזיר a, אחרת b   (מחזיר את הראשון ה-truthy)

const name = user.name || "Anonymous";   // ברירת מחדל אם falsy
user.isAdmin && showAdminPanel();         // הרץ רק אם truthy

Nullish Coalescing (??) — החלופה המדויקת

|| נופל על כל falsy — כולל 0 ו-"", שלפעמים הם ערכים תקינים! ?? נופל רק על null/undefined:

const count = 0;
const a = count || 10;   // 10  — באג! 0 נחשב falsy
const b = count ?? 10;   // 0   — נכון! 0 הוא ערך תקין

הכלל: ?? ל"ברירת מחדל אם חסר ערך", || ל"ברירת מחדל אם falsy". רוב הזמן אתה רוצה ??.

Optional Chaining (?.)

user?.address?.city   // אם user או address הם null/undefined → undefined (בלי קריסה)
user?.getName?.()     // קורא למתודה רק אם קיימת
arr?.[0]              // גישה בטוחה לאינדקס

מונע את השגיאה הקלאסית "Cannot read property of undefined". במקום user && user.address && user.address.city, פשוט user?.address?.city.

Ternary ו-spread

const label = age >= 18 ? "adult" : "minor";   // ternary

const arr2 = [...arr1, 4, 5];      // spread — מרחיב מערך
const obj2 = { ...obj1, x: 99 };   // spread — מרחיב object (ומדריס x)

5.5 Control Flow ופתרון בעיות — להפוך דרישה לקוד

Control flow הוא הסדר שבו statements מתבצעים. בלי תנאים ולולאות, התוכנית הייתה מריצה כל שורה פעם אחת מלמעלה למטה. ‏if בוחר מסלול; loop חוזרת על פעולה; ‏break,‏ continue ו־return משנים את הזרימה.

if, else if ו־else

function getAccessLevel(user) {
  if (!user) {
    return "anonymous";
  }

  if (user.isAdmin) {
    return "admin";
  }

  if (user.isActive) {
    return "member";
  }

  return "inactive";
}

ה־return המוקדם הוא guard clause: הוא מסיים case מיוחד ומונע nesting עמוק. סדר התנאים חשוב—admin פעיל מתאים גם ל־isActive, ולכן בודקים את הכלל הספציפי קודם.

for...of — ברירת המחדל למעבר על ערכים

const users = [
  { name: "Dana", active: true },
  { name: "Avi", active: false },
];

for (const user of users) {
  console.log(user.name);
}

user הוא הערך הנוכחי בכל איטרציה. השתמש ב־for...of כשאתה רוצה לקרוא ערכים, לבצע כמה צעדים, להשתמש ב־break/continue או לעשות await סדרתי.

for הקלאסית

for (let index = 0; index < users.length; index += 1) {
  const user = users[index];
  console.log(index, user.name);
}

ללולאה שלושה חלקים: initialization פעם אחת; condition לפני כל איטרציה; update אחרי כל איטרציה. השתמש בה כשאתה באמת צריך לשלוט ב־index או בקפיצות. אם צריך רק index לצד value, ‏users.entries() עם for...of לעיתים ברור יותר.

while ו־do...while

let attempts = 0;
while (attempts < 3 && !connected) {
  connected = tryConnect();
  attempts += 1;
}

while מתאימה כאשר מספר החזרות אינו ידוע מראש והמשך הלולאה תלוי ב־state. ודא שבתוך הלולאה משהו מקרב את condition ל־false, אחרת נוצרת infinite loop. ‏do...while מבצעת פעם אחת לפני בדיקת התנאי ולכן נדירה יותר.

break ו־continue

let selectedUser = null;

for (const user of users) {
  if (!user.active) {
    continue;                 // דלג למשתמש הבא
  }

  if (user.id === targetId) {
    selectedUser = user;
    break;                    // מצאנו — אין צורך להמשיך
  }
}

איך בוחרים בין Loop למתודת Array?

כוונהכלי ברור
לייצר ערך חדש מכל איברmap
לשמור רק איברים מתאימיםfilter
למצוא איבר ראשוןfind
לבדוק אם לפחות אחד/כולםsome / every
כמה צעדים, break/continue או state מורכבfor...of
חזרה עד שתנאי משתנהwhile

אין פרס על one-liner. אם אתה עדיין לומד או שהלוגיקה כוללת כמה counters ו־conditions, loop מפורשת יכולה להיות נכונה וקריאה יותר מ־reduce מורכב.

דוגמה: מדרישה ל־State

הדרישה: “החזר את שמות המשתמשים הפעילים ואת גילם הממוצע”. לפני קוד, מזהים מה צריך לשמור: array של שמות, סכום גילאים וכמות גילאים. אלה משתני ה־state של האלגוריתם.

function analyzeActiveUsers(users) {
  const names = [];
  let ageTotal = 0;
  let ageCount = 0;

  for (const user of users) {
    if (!user.active) continue;

    names.push(user.name);

    if (user.age !== null && user.age !== undefined) {
      ageTotal += user.age;
      ageCount += 1;
    }
  }

  return {
    names,
    averageAge: ageCount === 0 ? null : ageTotal / ageCount,
  };
}

החלק החשוב אינו לזכור push. הוא להבין שלממוצע צריך sum וגם count, וש־age חסר שונה מ־age ששווה אפס. זו בדיוק חשיבת decomposition.

לפני הפרק הבא: עבור על מדריך פתרון הבעיות. הוא מראה את התהליך המלא: דרישה → input/output → edge cases → pseudocode → קוד → tests → feature → פרויקט.

6. Functions

פונקציה היא יחידת התנהגות בעלת שם: היא מקבלת inputs, מבצעת פעולה ומחזירה output. היא מאפשרת לפרק בעיה גדולה לחלקים שאפשר להבין ולבדוק בנפרד. רק אחרי הבסיס הזה חשוב לדעת שפונקציות הן גם first-class citizens—אפשר להעביר אותן, להחזיר אותן ולשמור אותן במשתנים.

function calculateTotal(price, quantity) {
  const total = price * quantity;
  return total;
}

const result = calculateTotal(19.9, 3);

price ו־quantity הם parameters בהגדרה; ‏19.9 ו־3 הם arguments בקריאה. ‏return מסיים את הפונקציה ומחזיר ערך. פונקציה בלי return מפורש מחזירה undefined.

שלוש צורות הגדרה

// 1. Function Declaration — מורם (hoisted) לגמרי
function add(a, b) { return a + b; }

// 2. Function Expression — לא מורם (המשתנה כן, הערך לא)
const add2 = function(a, b) { return a + b; };

// 3. Arrow Function — קצר, ו-this שונה (פרק 8!)
const add3 = (a, b) => a + b;
const square = x => x * x;           // סוגר אחד — בלי סוגריים
const makeObj = () => ({ x: 1 });    // מחזיר object — צריך סוגריים!

ההבדל ב-hoisting

Function declarations מורמות לגמרי — אפשר לקרוא להן לפני ההגדרה. Function expressions ו-arrows לא — הן כפופות ל-TDZ של המשתנה (פרק 2):

sayHi();                    // ✅ עובד — declaration מורמת
function sayHi() {}

sayBye();                   // ❌ ReferenceError — expression לא
const sayBye = () => {};

פרמטרים — default, rest

function greet(name, greeting = "Hello") {   // default value
  return `${greeting}, ${name}`;
}

function sum(...numbers) {   // rest — אוסף את כל הארגומנטים למערך
  return numbers.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4);   // 10

Higher-Order Functions

פונקציה שמקבלת פונקציה כארגומנט או מחזירה פונקציה. זה הבסיס ל-map/filter/reduce ולכל הדפוסים הפונקציונליים:

const numbers = [1, 2, 3];
numbers.map(n => n * 2);          // מקבל פונקציה — [2, 4, 6]

function multiplier(factor) {     // מחזיר פונקציה (זה גם closure — פרק 7)
  return x => x * factor;
}
const double = multiplier(2);
double(5);   // 10

IIFE — Immediately Invoked Function Expression

(function() {
  // רץ מיד, יוצר scope מבודד
})();

דפוס ישן ליצירת scope פרטי (לפני modules). פחות נחוץ היום עם ES modules, אבל תיתקל בו בקוד ותיק.

7. Scope ו-Closures — עמוק

Closures הם אחד המושגים החשובים והמבלבלים ב-JavaScript, ונשאלים כמעט בכל ראיון. נבנה אותם מהיסוד.

Lexical Scope — הבסיס

Scope הוא "היכן משתנה נגיש". ב-JS ה-scope הוא lexical — נקבע לפי מיקום הכתיבה בקוד, לא לפי מאיפה קוראים. פונקציה פנימית רואה את המשתנים של הפונקציות שעוטפות אותה:

const outer = "I'm outer";
function parent() {
  const middle = "I'm middle";
  function child() {
    console.log(outer, middle);   // ✅ רואה את שניהם — scope chain
  }
  child();
}

ה-scope chain: משתנה מחפשים קודם בפונקציה הנוכחית, ואם לא נמצא — בעוטפת, וכן הלאה עד ה-global.

Closure — ההגדרה

Closure הוא פונקציה ש"זוכרת" את ה-scope שבו היא נוצרה, גם אחרי שה-scope הזה הסתיים. כשפונקציה מחזירה פונקציה פנימית, הפנימית "סוחבת איתה" גישה למשתנים של החיצונית — גם אחרי שהחיצונית סיימה לרוץ. זה הקסם.

function counter() {
  let count = 0;                 // משתנה "פרטי"
  return function() {
    count++;                     // הפונקציה הפנימית זוכרת את count
    return count;
  };
}

const inc = counter();
inc();   // 1
inc();   // 2
inc();   // 3
// count "חי" בין הקריאות — הוא סגור (closed over) בתוך ה-closure

שים לב: counter() כבר סיימה לרוץ, אבל count לא נעלם — ה-closure מחזיק אותו בחיים. כל קריאה ל-counter() יוצרת count חדש ונפרד.

למה closures חשובים — שימושים אמיתיים

  • מצב פרטי (encapsulation) — count נגיש רק דרך הפונקציה, לא מבחוץ. זה "private" אמיתי לפני #fields.
  • Factory functions — multiplier(2) מפרק 6 הוא closure שזוכר את factor.
  • Callbacks ו-event handlers — כל callback שמשתמש במשתנה חיצוני הוא closure.
  • Memoization, debounce, throttle — כולם בנויים על closures.

המלכודת הקלאסית: closures בלולאה

הבאג המפורסם ביותר עם closures (ולמה let חשוב):

// ❌ עם var — כולם מדפיסים 3!
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);   // 3, 3, 3
}
// כי var function-scoped — יש i אחד משותף, וכשה-timeout רץ i כבר 3.

// ✅ עם let — 0, 1, 2
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);   // 0, 1, 2
}
// כי let block-scoped — כל איטרציה יוצרת i חדש, וכל closure זוכר את שלו.

זו דוגמה מושלמת לאיך scope ו-closures מתחברים — ולמה let פותר באג אמיתי.

8. this — הנושא הקשה ביותר

אם יש מושג אחד ב-JavaScript שמבלבל את כולם — זה this. הבעיה: this לא נקבע לפי איפה הפונקציה מוגדרת, אלא לפי איך היא נקראת. נפרק את כל הכללים.

ארבעת הכללים של this

ערך this נקבע לפי צורת הקריאה, בסדר עדיפות:

1. Method call — this = האובייקט

const user = {
  name: "Eliya",
  greet() { return `Hi, ${this.name}`; }
};
user.greet();   // this = user → "Hi, Eliya"

2. Function call רגיל — this = undefined (strict) / global

function show() { return this; }
show();   // undefined (ב-strict mode / modules) או global object

3. Explicit — call / apply / bind

function greet() { return `Hi, ${this.name}`; }
const user = { name: "Dan" };

greet.call(user);       // this = user (ארגומנטים אחד-אחד)
greet.apply(user);      // this = user (ארגומנטים כמערך)
const bound = greet.bind(user);   // מחזיר פונקציה חדשה עם this קבוע
bound();                // this = user לתמיד

4. Constructor call — this = ה-instance החדש

function User(name) { this.name = name; }
const u = new User("Eliya");   // this = ה-object החדש

המלכודת הקלאסית: this "נאבד"

כשמעבירים method כ-callback, this "מתנתק" מהאובייקט — כי מה שקובע זה איך קוראים, וה-callback נקרא כפונקציה רגילה:

const user = {
  name: "Eliya",
  greet() { return `Hi, ${this.name}`; }
};

setTimeout(user.greet, 100);   // ❌ this = undefined! "Hi, undefined"
// כי setTimeout קורא ל-greet כפונקציה רגילה, מנותקת מ-user.

setTimeout(() => user.greet(), 100);   // ✅ arrow שומר, קורא נכון
setTimeout(user.greet.bind(user), 100); // ✅ או bind

Arrow Functions ו-this — הפתרון

ל-arrow functions אין this משלהן — הן "יורשות" את this מה-scope הלקסיקלי שבו נוצרו (בדיוק כמו closure). זו הסיבה שהן פתרו את רוב כאב ה-this:

class Timer {
  constructor() {
    this.seconds = 0;
    // ❌ function רגילה — this מתנתק:
    setInterval(function() { this.seconds++; }, 1000);   // this = undefined
    // ✅ arrow — this נשאר ה-instance:
    setInterval(() => { this.seconds++; }, 1000);        // this = Timer
  }
}

הכלל המעשי: השתמש ב-arrow functions ל-callbacks כדי לשמר this. אבל אל תשתמש ב-arrow ל-methods של object (כי אז this לא יהיה האובייקט אלא ה-scope החיצוני). זו הבחנה עדינה ששווה להפנים.

9. Objects

Objects הם אוספי צמדים של key-value, והם הבסיס כמעט לכל דבר ב-JS (מערכים, פונקציות — הכל objects מתחת).

יצירה וגישה

const user = {
  name: "Eliya",
  age: 30,
  greet() { return `Hi, ${this.name}`; },   // method (shorthand)
};

user.name;         // dot notation
user["name"];      // bracket notation (למפתחות דינמיים)
const key = "age";
user[key];         // 30 — bracket מאפשר מפתח ממשתנה

Computed properties ו-shorthand

const field = "email";
const obj = {
  [field]: "e@x.com",   // computed key — הופך ל-"email"
  name,                 // shorthand — אם המשתנה name קיים, זהה ל-name: name
};

מתודות שימושיות של Object

Object.keys(obj)        // מערך המפתחות
Object.values(obj)      // מערך הערכים
Object.entries(obj)     // מערך של [key, value] זוגות
Object.assign({}, a, b) // מיזוג objects (או: {...a, ...b})
Object.freeze(obj)      // הופך ל-immutable (shallow)
"name" in obj           // בדיקת קיום מפתח

Getters ו-Setters

const temp = {
  _celsius: 0,
  get celsius() { return this._celsius; },
  set celsius(value) {
    if (value < -273.15) throw new Error("Below absolute zero");
    this._celsius = value;
  }
};
temp.celsius = 25;      // קורא ל-setter
temp.celsius;           // קורא ל-getter

Shallow מול Deep copy

זוכר reference מפרק 3? העתקת object דורשת מחשבה. {...obj} ו-Object.assign עושים shallow copy — מעתיקים את הרמה הראשונה, אבל objects מקוננים עדיין משותפים (reference):

const original = { name: "Eliya", address: { city: "TLV" } };
const copy = { ...original };
copy.address.city = "Haifa";
console.log(original.address.city);   // "Haifa"! — הפנימי משותף

// deep copy אמיתי:
const deep = structuredClone(original);   // מודרני, מובנה

10. Prototypes ו-Inheritance

זה הלב של ה-OOP ב-JavaScript, ומה שמבדיל אותה משפות class-based כמו Java. גם אם אתה משתמש ב-class (פרק 11), חשוב להבין שמתחת הכל זה prototypes.

הרעיון: Prototype Chain

לכל object ב-JS יש קישור נסתר לאובייקט אחר — ה-prototype שלו. כשמחפשים property על object ולא מוצאים, JS מטפס ל-prototype, ואם לא שם — ל-prototype שלו, וכן הלאה עד null. זו ה-prototype chain:

const arr = [1, 2, 3];
arr.map(...)     // map לא על arr עצמו — הוא על Array.prototype!
// arr → Array.prototype → Object.prototype → null
// JS מטפס בשרשרת עד שמוצא את map

זו הסיבה שכל מערך "יודע" map/filter — הם לא בכל מערך, אלא ב-Array.prototype אחד שכולם מקושרים אליו. חיסכון עצום בזיכרון, ומנגנון הירושה של השפה.

prototype מול __proto__

  • __proto__ (או Object.getPrototypeOf(obj)) — הקישור של instance ל-prototype שלו.
  • prototype — property של constructor functions, שממנו ה-instances יורשים.
function Animal(name) { this.name = name; }
Animal.prototype.speak = function() { return `${this.name} speaks`; };

const dog = new Animal("Rex");
dog.speak();                       // "Rex speaks" — נמצא ב-prototype
dog.__proto__ === Animal.prototype;  // true

למה זה חשוב גם אם אתה משתמש ב-class: ES6 class הוא syntactic sugar מעל prototypes — מתחת, זה בדיוק המנגנון הזה. כשאתה מבין prototype chain, אתה מבין למה instanceof עובד, איך ירושה עובדת, ולמה הוספת method ל-Array.prototype משפיעה על כל המערכים. זה ההבדל בין לדעת את התחביר להבין את השפה.

11. Classes

ES6 הוסיף תחביר class — נוח ומוכר משפות אחרות, אבל זכור: מתחת זה prototypes (פרק 10). (כיסינו classes לעומק ב-TypeScript — כאן הזווית של JS טהור).

class Animal {
  #secret = "hidden";        // private field (# — פרטי אמיתי ב-runtime)

  constructor(name) {
    this.name = name;        // instance field
  }

  speak() {                  // method — נכנס ל-prototype מאחורי הקלעים
    return `${this.name} speaks`;
  }

  static create(name) {      // static — על ה-class, לא על instance
    return new Animal(name);
  }
}

class Dog extends Animal {   // ירושה
  constructor(name, breed) {
    super(name);             // קורא ל-constructor של האב
    this.breed = breed;
  }
  speak() {                  // override
    return `${super.speak()} — woof`;
  }
}

const d = new Dog("Rex", "Lab");
d.speak();                   // "Rex speaks — woof"
d instanceof Animal;         // true (דרך prototype chain)

הנקודות: #field הוא פרטיות אמיתית ב-runtime (בניגוד ל-private של TypeScript שהוא compile-time בלבד — זוכר?). static שייך ל-class. extends+super לירושה. וכל method נכנס ל-prototype, לא לכל instance.

12. Arrays ומתודות מערך

מערכים ומתודותיהם הם כלי העבודה היומיומי. שליטה במתודות הפונקציונליות (map/filter/reduce) היא חובה — הן מחליפות רוב הלולאות.

המתודות שמשנות (mutating) מול לא-משנות

// ⚠️ משנות את המערך המקורי:
arr.push(x)      // מוסיף בסוף
arr.pop()        // מסיר מהסוף
arr.shift()      // מסיר מההתחלה
arr.unshift(x)   // מוסיף בהתחלה
arr.splice(i, n) // מסיר/מוסיף באמצע
arr.sort()       // ממיין (במקום!)
arr.reverse()    // הופך

// ✅ מחזירות מערך חדש (לא משנות):
arr.slice(i, j)  // חותך תת-מערך
arr.concat(arr2) // מחבר
[...arr]         // עותק

המתודות הפונקציונליות — הליבה

const nums = [1, 2, 3, 4, 5];

nums.map(n => n * 2)          // [2,4,6,8,10] — טרנספורמציה
nums.filter(n => n % 2 === 0) // [2,4] — סינון
nums.reduce((acc, n) => acc + n, 0)  // 15 — צמצום לערך אחד
nums.forEach(n => console.log(n))    // side effect, לא מחזיר
nums.find(n => n > 3)         // 4 — הראשון שמתאים
nums.findIndex(n => n > 3)    // 3 — האינדקס
nums.some(n => n > 4)         // true — האם יש לפחות אחד
nums.every(n => n > 0)        // true — האם כולם
nums.includes(3)             // true — האם מכיל

reduce — החזק והמבלבל ביותר

reduce מצמצם מערך לערך אחד, בכל צעד צובר תוצאה. הוא נראה מסובך אבל הוא הבסיס להרבה:

// סכום:
[1,2,3].reduce((acc, n) => acc + n, 0);   // 6

// קיבוץ (group by) — reduce על steroids:
const users = [{role:"admin"}, {role:"user"}, {role:"admin"}];
users.reduce((acc, u) => {
  acc[u.role] = (acc[u.role] || 0) + 1;
  return acc;
}, {});   // { admin: 2, user: 1 }

acc הוא הצובר (מתחיל מהערך השני של reduce), n האיבר הנוכחי. כמעט כל map/filter אפשר לבטא ב-reduce — אבל השתמש ב-map/filter כשמתאים, הם קריאים יותר.

chaining — שרשור

// המתודות שמחזירות מערך ניתנות לשרשור — קריא וחזק:
const result = users
  .filter(u => u.isActive)
  .map(u => u.name)
  .sort();

13. Strings ומתודות מחרוזת

const s = "Hello World";
s.length              // 11
s.toUpperCase()       // "HELLO WORLD"
s.toLowerCase()
s.trim()              // מסיר רווחים מהקצוות
s.includes("World")   // true
s.startsWith("Hello") // true
s.endsWith("World")   // true
s.indexOf("o")        // 4 — מיקום ראשון
s.slice(0, 5)         // "Hello" — תת-מחרוזת
s.replace("World", "JS")     // "Hello JS" (ראשון)
s.replaceAll("o", "0")       // "Hell0 W0rld"
s.split(" ")          // ["Hello", "World"] — למערך
s.repeat(3)
s.padStart(15, "*")   // ריפוד

חשוב: strings הם immutable — כל המתודות מחזירות string חדש, לא משנות את המקורי. s[0] נותן תו, אבל s[0] = "X" לא עובד.

14. Destructuring, Spread/Rest, Template Literals

Destructuring — פירוק

// Array destructuring:
const [first, second, ...rest] = [1, 2, 3, 4];
// first=1, second=2, rest=[3,4]

// Object destructuring:
const { name, age, role = "user" } = user;   // עם default
const { name: userName } = user;              // שינוי שם

// בפרמטרים — נפוץ מאוד:
function greet({ name, greeting = "Hi" }) {
  return `${greeting}, ${name}`;
}
greet({ name: "Eliya" });

// החלפת משתנים בשורה אחת:
[a, b] = [b, a];

Template Literals

const name = "Eliya";
const msg = `Hello ${name}, you are ${age >= 18 ? "adult" : "minor"}`;
// interpolation עם ${}, ותומך בכמה שורות:
const html = `
  <div>${name}</div>
`;

Spread/Rest — הסיכום

// Spread — "פורש":
Math.max(...[1, 2, 3]);        // מפזר מערך לארגומנטים
const merged = [...a, ...b];   // מחבר מערכים
const clone = { ...obj };      // מעתיק object

// Rest — "אוסף":
function f(...args) {}         // אוסף ארגומנטים
const [head, ...tail] = arr;   // אוסף את השאר

אותו סימן ..., משמעות הפוכה לפי הקשר: spread פורש, rest אוסף.

15. Async — Promises, async/await, Event Loop

קוד אסינכרוני הוא לב ה-JavaScript. כיסינו את ה-event loop לעומק במדריך Node — כאן הזווית של השפה: איך כותבים async נכון. (התיאוריה המלאה של ה-event loop — במדריך Node).

הבעיה: JS הוא single-threaded

JS רץ על thread אחד. פעולות איטיות (רשת, timers) לא יכולות "לחסום" — אז הן אסינכרוניות: מתחילות, וה-callback שלהן רץ מאוחר יותר כשה-thread פנוי. זה מנוהל על ידי ה-event loop (מדריך Node).

Promise — ההפשטה

Promise הוא object שמייצג ערך עתידי, בשלושה מצבים: pending → fulfilled (הצליח) או rejected (נכשל):

const p = new Promise((resolve, reject) => {
  setTimeout(() => resolve("done"), 1000);   // או reject(err)
});

p.then(result => console.log(result))    // הצלחה
 .catch(err => console.error(err))       // כישלון
 .finally(() => console.log("cleanup")); // תמיד

async/await — המודרני

סוכר תחבירי על Promises שנראה סינכרוני. זה מה שתכתוב:

async function getUser(id) {
  try {
    const res = await fetch(`/users/${id}`);   // "ממתין" בלי לחסום
    const user = await res.json();
    return user;
  } catch (err) {
    console.error("Failed:", err);
  }
}
// async function תמיד מחזירה Promise

Promise combinators — הכלים החשובים

// כולם במקביל, נכשל אם אחד נכשל:
const [a, b] = await Promise.all([fetchA(), fetchB()]);

// כולם, לא נכשל — מחזיר סטטוס לכל אחד:
const results = await Promise.allSettled([fetchA(), fetchB()]);

// הראשון שמסתיים (הצלחה או כישלון):
const fastest = await Promise.race([fetchA(), fetchB()]);

// הראשון שמצליח:
const first = await Promise.any([fetchA(), fetchB()]);

המלכודת: סדרתי מול מקבילי (חוזר ממדריך Node)

await ברצף מריץ דברים בזה אחר זה. לדברים עצמאיים — בזבוז זמן. Promise.all מריץ במקביל:

// ❌ סדרתי — איטי (200ms):
const a = await fetchA();   // 100ms
const b = await fetchB();   // עוד 100ms

// ✅ מקבילי — מהיר (100ms):
const [a, b] = await Promise.all([fetchA(), fetchB()]);

Microtasks — למה Promise קודם ל-setTimeout

Promise callbacks הם microtasks — עדיפות על macrotasks כמו setTimeout. זו הסיבה שסדר הריצה מפתיע (כיסינו את זה לעומק במדריך Node, פרק ה-event loop):

console.log(1);
setTimeout(() => console.log(2), 0);     // macrotask
Promise.resolve().then(() => console.log(3));  // microtask
console.log(4);
// פלט: 1, 4, 3, 2

16. Modules

מודולים מאפשרים לפצל קוד לקבצים ולשתף ביניהם. (כיסינו CJS מול ESM לעומק במדריך Node — כאן התחביר של ESM, הסטנדרט):

// math.js — export
export function add(a, b) { return a + b; }
export const PI = 3.14;
export default class Calculator {}   // default — אחד לקובץ

// app.js — import
import Calculator, { add, PI } from "./math.js";
import * as math from "./math.js";   // הכל כ-namespace

ההמלצה (חוזרת מ-TypeScript/Node): העדף named exports — עקביים וידידותיים ל-refactoring. כל קובץ הוא module עם scope משלו — אין זיהום global.

17. Error Handling

try {
  riskyOperation();
} catch (err) {
  console.error(err.message);
} finally {
  cleanup();   // רץ תמיד — הצלחה או כישלון
}

// זריקת שגיאה:
throw new Error("Something broke");

// Error types מובנים:
// Error, TypeError, RangeError, SyntaxError, ReferenceError

// Custom error:
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}
throw new ValidationError("Invalid email", "email");

כללים (חוזרים ממדריך Node): ב-async, try/catch סביב await תופס שגיאות. שכחת await? השגיאה הופכת ל-unhandled rejection שמפילה את התהליך. ותמיד throw new Error(...) (object), לא throw "string" — כדי שיהיה stack trace. ה-catch ב-JS תופס כל מה שנזרק, אז בדוק err instanceof Error אם צריך.

18. Iterators, Generators, Symbol, Map/Set

Map ו-Set — מבני נתונים חשובים

// Map — key-value, כל טיפוס כמפתח (לא רק string כמו object):
const map = new Map();
map.set("key", 1);
map.set(objKey, 2);      // גם object כמפתח!
map.get("key");          // 1
map.has("key");          // true
map.size;                // 2

// Set — ערכים ייחודיים:
const set = new Set([1, 2, 2, 3]);   // {1, 2, 3}
set.has(2);              // true
[...new Set(arr)]        // טריק להסרת כפילויות ממערך!

Map עדיף על object כשהמפתחות דינמיים או לא-strings, ושומר סדר הכנסה. Set מושלם לייחודיות.

Symbol — מזהה ייחודי

const id = Symbol("id");   // ערך ייחודי לחלוטין
const obj = { [id]: 123 }; // מפתח שלא יתנגש עם אחרים

שימושי למפתחות "נסתרים" ולמנוע התנגשויות. פחות נפוץ בקוד יומיומי.

Iterators ו-Generators

Iterable הוא כל דבר שאפשר לעבור עליו עם for...of (arrays, strings, Map, Set). Generator הוא פונקציה שיכולה "לעצור ולהמשיך" — מייצרת ערכים לפי דרישה:

function* idGenerator() {   // * = generator
  let id = 1;
  while (true) {
    yield id++;             // "מחזיר" ערך ומשהה עד הקריאה הבאה
  }
}
const gen = idGenerator();
gen.next().value;   // 1
gen.next().value;   // 2 — ממשיך מאיפה שעצר

Generators שימושיים ל-lazy sequences, streams אינסופיים, ו-state machines. מתקדם, אבל שווה להכיר.

for...of מול for...in

for (const val of [10, 20, 30]) { }   // ✅ ערכים (iterables)
for (const key in obj) { }             // מפתחות (objects) — זהירות!

מלכודת: for...in על מערך נותן אינדקסים כ-strings וגם properties מ-prototype. למערכים השתמש ב-for...of או במתודות (forEach/map).

20. Best Practices ותרגילים

Best Practices

  1. const כברירת מחדל, let כשצריך, var אף פעם.
  2. === תמיד, לא ==.
  3. ?? ל-defaults (לא || כש-0/"" תקינים), ?. לגישה בטוחה.
  4. arrow functions ל-callbacks (שומר this), function רגילה ל-methods.
  5. map/filter/reduce על לולאות, כשמתאים — קריא ופונקציונלי.
  6. זכור value מול reference — העתק objects במפורש.
  7. async/await + try/catch, ותמיד await כל Promise.
  8. Promise.all לעבודה מקבילה, לא await סדרתי.
  9. destructuring ו-spread לקוד נקי.
  10. שקול TypeScript — הוא תופס את רוב ה-gotchas האלה מראש (יש לך מדריך!).

תרגילים

1 — Coercion. נבא את התוצאה של: [] + [], [] + {}, 1 + "2" + 3, "5" - 2, null == undefined, NaN === NaN. הרץ ובדוק.

2 — Closure. כתוב createCounter() שמחזיר object עם increment, decrement, ו-get — כשה-count פרטי (closure, לא נגיש מבחוץ).

3 — this. קח object עם method, העבר את ה-method כ-callback ל-setTimeout, וראה את ה-this "נאבד". תקן בשלוש דרכים: arrow, bind, wrapper.

4 — Array methods. בהינתן מערך של objects (users עם name, age, role), כתוב שרשור אחד שמחזיר את שמות ה-admins הבוגרים, ממוינים. השתמש ב-filter+map+sort.

5 — reduce. ממש groupBy(arr, key) עם reduce — מקבץ מערך של objects לפי ערך של property.

6 — Prototype. צור "class" בלי תחביר class — constructor function + methods על ה-prototype. ואז שכתב אותו עם class וראה שזה זהה.

7 — Async. כתוב פונקציה שמביאה מ-3 endpoints. ממש סדרתית ומקבילית (Promise.all), ומדוד את ההפרש.

סיכום — מה הלאה

שני דברים מעל הכל: רוב ה"טירוף" של JavaScript נובע משני מנגנונים — type coercion (פרק 4) ו-reference מול value (פרק 3). כשאתה מבין אותם, הכל צפוי. והשני: closures, this, ו-prototypes הם שלושת המושגים שמפרידים בין "כותב JS" ל"מבין JS" — הם נשאלים בכל ראיון ומופיעים בכל קוד.

וזה סוגר את השלישייה של הבסיס: JavaScript (השפה, זה), TypeScript (הטיפוסים מעליה), ו-Node (ה-runtime שמריץ אותה). שלושתם יחד הם הרצפה המלאה. שים לב: הרבה מה-gotchas כאן הם בדיוק מה ש-TypeScript בא לפתור — עכשיו אתה מבין למה הוא קיים, לא רק איך להשתמש בו.
