1. Files, Paths ו־I/O

Text מול Binary

קובץ הוא רצף bytes. כאשר פותחים אותו ב־text mode, Python מוסיפה שכבת encoding/decoding ומחזירה str. ב־binary mode מקבלים bytes ללא פרשנות. תמונה, ZIP או פרוטוקול בינארי נפתחים ב־rb; JSON או טקסט ב־r עם encoding מפורש.

from pathlib import Path

text_path = Path("data/notes.txt")
with text_path.open("r", encoding="utf-8") as file:
    content = file.read()

image_path = Path("assets/photo.png")
with image_path.open("rb") as file:
    header = file.read(8)

with סוגר את file descriptor גם אם parsing נכשל. הסתמכות על garbage collector לסגירה יכולה להשאיר descriptors פתוחים זמן לא ידוע ולגרום לשגיאת “too many open files”.

Streaming במקום טעינה מלאה

read() בלי size טוען את כל הקובץ לזיכרון. עבור קובץ של 10GB זה עלול להפיל process. file object הוא iterable שמחזיר שורה בכל פעם, ולכן אפשר לעבד memory קבוע בקירוב.

with Path("events.jsonl").open(encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        if not line.strip():
            continue
        process_line(line_number, line)

Atomic Write

אם התהליך קורס באמצע כתיבה ישירה, הקובץ עלול להישאר חלקי. דפוס בטוח יותר הוא לכתוב לקובץ זמני באותה filesystem, לבצע flush לפי דרישת durability, ואז replace. Rename באותה filesystem הוא בדרך כלל atomic מבחינת visibility: קורא רואה את הגרסה הישנה או החדשה, לא חצי קובץ.

import json
from pathlib import Path

def atomic_write_json(path: Path, data: object) -> None:
    temporary = path.with_suffix(path.suffix + ".tmp")
    temporary.write_text(
        json.dumps(data, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
    temporary.replace(path)

זה אינו פותר שתי כתיבות מקבילות; בשבילן צריך ownership, lock, optimistic version או database.

2. Serialization וגבולות אמון

Serialization ממירה object למבנה שניתן לשמור או להעביר; deserialization עושה את הכיוון ההפוך. JSON מכיר object, array, string, number, boolean ו־null. הוא אינו מכיר datetime, Decimal, UUID או class שלך, ולכן צריך wire representation מפורש.

from dataclasses import asdict
from datetime import datetime, timezone

payload = {
    "version": 2,
    "created_at": datetime.now(timezone.utc).isoformat(),
    "task": asdict(task),
}

Schema version מאפשר לקרוא נתונים ישנים ולבצע migration. אל תערבב domain object עם JSON dictionary בכל הקוד; parser אחד מאמת את הגבול ומייצר model תקין.

אבטחה: JSON הוא data. ‏Pickle הוא פרוטוקול Python שיכול לשחזר objects באמצעות ביצוע הוראות. לעולם אל תעשה unpickle למידע ממקור לא מהימן. Type hints גם אינן מאמתות JSON בזמן ריצה; השתמש ב־validation מפורש או library כמו Pydantic בגבול.

3. Testing לעומק

מה בדיקה מנסה להוכיח?

בדיקה אינה רק “להריץ שורה”. היא מציגה scenario, מפעילה behavior ובודקת outcome שניתן לצפייה. מבנה Arrange–Act–Assert עוזר להפריד הכנה, פעולה ואימות.

def test_transfer_moves_balance_between_accounts():
    # Arrange
    source = Account(balance=100)
    target = Account(balance=20)

    # Act
    transfer(source, target, amount=30)

    # Assert
    assert source.balance == 70
    assert target.balance == 50

Unit, Integration ו־E2E

סוגמה הוא בודקיתרון ומגבלה
Unitיחידת לוגיקה עם dependencies נשלטותמהירה ומדויקת, אך לא מוכיחה integration
Integrationשיתוף פעולה עם DB, filesystem או broker אמיתימוצאת אי־התאמות, אך איטית יותר
E2Eflow דרך interface ציבוריביטחון גבוה בזרימה, diagnosis קשה יותר

Fixtures, Parametrize ו־Mocks

@pytest.mark.parametrize(
    ("amount", "expected_error"),
    [(0, ValueError), (-1, ValueError), (101, InsufficientBalanceError)],
)
def test_transfer_rejects_invalid_amounts(amount, expected_error):
    with pytest.raises(expected_error):
        transfer(Account(100), Account(0), amount)

Mock מתאים לגבול חיצוני או nondeterministic כמו clock, email או payment provider. Mock של כל method פנימית מצמיד את הבדיקה ליישום, ולכן refactor שומר behavior עלול לשבור tests. Fake קטן שמממש Protocol הוא לעיתים ברור יותר.

Regression test משחזרת bug לפני התיקון ואז נשארת כדי למנוע חזרה. Coverage אומר אילו שורות רצו; הוא אינו מוכיח assertions טובים או edge cases.

4. Debugging, Logging ו־Tracebacks

דיבוג טוב מתחיל ב־reproduction קטן ועקבי. קרא traceback מלמטה כדי לראות את exception וההודעה, ואז עקוב למעלה כדי להבין את מסלול הקריאות. אל תתקן סימפטום לפני שאתה יכול להסביר את state שהוביל אליו.

def calculate_ratio(total: int, count: int) -> float:
    breakpoint()
    return total / count

breakpoint() מאפשר לבדוק variables, call stack ולהתקדם שורה־שורה. בפרודקשן משתמשים ב־structured logging ו־observability, לא ב־print אקראי.

logger.info(
    "order created",
    extra={"order_id": order.id, "customer_id": order.customer_id},
)

Log צריך לתאר event עם fields יציבים, level מתאים ו־correlation ID. אל תכתוב password, access token, full payment data או מידע רגיש. ‏logger.exception בתוך except שומר traceback; הודעת שגיאה בלי traceback לעיתים מאבדת את המידע החשוב ביותר.

5. Asyncio מהיסודות

Concurrency אינה Parallelism

Concurrency היא היכולת לקדם כמה משימות באותה תקופה, למשל לעבור למשימה אחרת בזמן שהראשונה מחכה לרשת. Parallelism היא ביצוע אמיתי באותו רגע על כמה cores. Asyncio מספקת בעיקר concurrency ל־I/O בתוך thread אחד.

Blocking מול Non-blocking

קריאת רשת סינכרונית חוסמת את thread עד שה־OS מחזיר תוצאה. בקריאה async, coroutine נרשמת להמשך ומבצעת await; ה־event loop יכול בינתיים להריץ coroutine אחרת. ‏await אינו “פותח thread” ואינו הופך פונקציה רגילה לאסינכרונית.

import asyncio

async def fetch_user(client, user_id: int):
    response = await client.get(f"/users/{user_id}")
    return response.json()

async def main():
    users = await asyncio.gather(
        fetch_user(client, 1),
        fetch_user(client, 2),
    )

asyncio.run(main())

קריאה ל־async def מחזירה coroutine object; הגוף מתחיל רק כאשר עושים await או מתזמנים Task. שכחת await עלולה ליצור warning ולא לבצע את הפעולה.

CPU-bound בתוך Event Loop

לולאת חישוב של חמש שניות שאינה עושה await תחסום את event loop לחמש שניות וכל הבקשות האחרות יחכו. Async מתאים ל־I/O; חישוב CPU כבד מועבר ל־process pool, worker נפרד או service מתאים.

6. Tasks, Cancellation ו־Structured Concurrency

Task עוטפת coroutine ומתזמנת אותה ב־event loop. יצירת אלפי Tasks מיד יכולה להציף connection pool או ספק חיצוני; לכן מגבילים concurrency באמצעות Semaphore או worker pool.

async def fetch_all(client, urls: list[str]):
    semaphore = asyncio.Semaphore(20)

    async def fetch(url: str):
        async with semaphore:
            async with asyncio.timeout(5):
                return await client.get(url)

    async with asyncio.TaskGroup() as group:
        tasks = [group.create_task(fetch(url)) for url in urls]
    return [task.result() for task in tasks]

Cancellation היא בקשה ש־coroutine צריכה לאפשר לה להתפשט אחרי cleanup. תפיסת CancelledError ובליעתה יכולה לגרום ל־shutdown תקוע. השתמש ב־try/finally לסגירת resource ואז re-raise.

TaskGroup הוא structured concurrency: המשימות שייכות ל־scope, והיציאה ממנו מחכה להן או מבטלת אחיות במקרה כשל. כך לא נשארות background tasks “יתומות”.

7. Threads, Race Conditions ו־Locks

Threads באותו process חולקות זיכרון. זה מקל להעביר objects, אבל שתי threads יכולות לקרוא ולשנות state באותו זמן. פעולה עסקית שנראית כשורה אחת עשויה להיות רצף read–compute–write שניתן לשלב.

import threading

balance = 100
lock = threading.Lock()

def withdraw(amount: int):
    global balance
    with lock:
        if balance >= amount:
            balance -= amount

בלי lock, שתי threads יכולות לקרוא balance=100, שתיהן לאשר משיכה של 80 ולכתוב 20—אחת המשיכות “נעלמה” מה־state. Lock מגדירה critical section ומבטיחה שרק thread אחת נמצאת בה. שמור אותה קצרה ואל תבצע בתוכה network call איטי.

Deadlock מתרחש כשכל thread מחזיקה resource ומחכה לאחר. מניעה כוללת סדר נעילות עקבי, צמצום nested locks ו־timeouts מתאימים. Condition Variable מאפשרת להמתין לשינוי state בלי polling; Semaphore מגבילה מספר משתמשים במשאב.

8. Processes, IPC וה־GIL

מהו ה־GIL?

ב־CPython המסורתי, Global Interpreter Lock מאפשר בדרך כלל ל־thread אחת לבצע Python bytecode בכל רגע בתוך process. הסיבה המרכזית היסטורית היא פישוט הגנת internals וניהול reference counts. ה־GIL משתחרר בזמן I/O ובחלק מספריות native.

לכן threads עדיין מועילות ל־I/O, אבל שתי threads שמבצעות Python CPU-bound לרוב לא ינצלו שני cores באופן מלא. ה־GIL גם אינו מבטיח correctness של הלוגיקה שלך: context switch יכול לקרות בין שלבי פעולה, ו־libraries עשויות לשחרר אותו.

Processes

Process נפרד מקבל memory address space ו־GIL משלו, ולכן כמה processes יכולים לבצע CPU work במקביל. המחיר הוא startup, יותר זיכרון והצורך להעביר מידע באמצעות serialization ו־IPC.

from concurrent.futures import ProcessPoolExecutor

with ProcessPoolExecutor() as pool:
    results = list(pool.map(calculate_checksum, paths))

הפונקציה וה־arguments צריכים להיות serializable לפי מנגנון ה־multiprocessing. העברת object ענק בין processes יכולה לעלות יותר מהחישוב. בחר task בגודל מספיק גדול ומדוד.

9. Memory Management ו־Garbage Collection

CPython משתמשת בעיקר ב־reference counting. לכל object נשמר בקירוב מספר references פעילים; כשהמספר יורד לאפס, אפשר לשחרר אותו מיד. השמה, container ו־argument יכולים להוסיף reference; מחיקת שם או יציאה מ־scope מורידות.

a = []          # reference אחד
b = a           # reference נוסף
del a           # האובייקט חי דרך b
del b           # כעת ניתן לשחרור

Reference cycle יוצר objects שמצביעים זה לזה גם כשאין גישה מבחוץ, ולכן count אינו מגיע לאפס. ה־cyclic garbage collector מאתר מחזורים מסוימים ומנקה אותם. ‏weakref מאפשר reference שאינו שומר object בחיים, שימושי ל־caches ו־registries מיוחדים.

Memory leak ב־Python אינה חייבת להיות זיכרון “שאי אפשר לשחרר”; לרוב זו reference שנשארה בטעות ב־global cache, listener, task או collection שגדלה בלי גבול. בדוק ownership ו־lifecycle לפני tuning של GC.

משאב חיצוני אינו זיכרון: socket, file ו־DB connection צריכים סגירה דטרמיניסטית עם context manager. GC אינה חוזה timing מתאים למשאבים כאלה.

10. Performance ו־Profiling

אופטימיזציה מתחילה במדידה. זמן בקשת Backend מתחלק לעיתים ל־DB, network, serialization ו־queueing; שיפור microsecond בלולאה לא יעזור אם query לוקחת 300ms.

  • timeit להשוואה קטנה ומבודדת.
  • cProfile למדידת זמן מצטבר לפי functions.
  • Sampling profiler לתמונה עם פחות overhead בפרודקשן.
  • tracemalloc למקור הקצאות זיכרון.
  • Metrics ו־tracing למדידה בתוך request אמיתי.

שפר קודם complexity, מספר queries, גודל payload ומספר round trips. אחר כך שקול caching, batching, generators או native libraries. Cache דורש key נכון, TTL, invalidation, size bound והתנהגות בכשל; אחרת הוא יוצר stale data או memory leak.

11. Production Backend Patterns

Boundaries ושכבות

HTTP handler צריך לתרגם request ל־input של use case ולתרגם result ל־response. Domain logic אינה צריכה לדעת על Django request, status code או ORM model אם אין צורך. הפרדה כזאת מאפשרת לבדוק business rules בלי server ובלי DB.

Timeout, Retry ו־Idempotency

לכל I/O חיצוני צריך timeout; בלי timeout worker עלול להיתקע ללא גבול. Retry מתאים לתקלה זמנית ולפעולה בטוחה. השתמש ב־exponential backoff ו־jitter כדי למנוע retry storm. POST שיוצר תשלום חייב idempotency key או הגנה אחרת, אחרת retry יכול ליצור כפילות.

Transactions

Transaction מקיפה invariant עסקי שצריך להיות אטומי. שמור אותה קצרה; network call בתוך transaction מחזיקה locks/connections בזמן לא ידוע. עבודה חיצונית אחרי commit יכולה להשתמש ב־outbox כאשר נדרשת אמינות בין database ל־message broker.

Lifecycle

ב־startup מאמתים configuration ויוצרים pools/clients. ב־request משתמשים במשאבים בגבולות. ב־shutdown מפסיקים לקבל traffic, מחכים ל־inflight עד deadline וסוגרים resources. Health, readiness ו־liveness הן בדיקות שונות—אל תשתמש ב־liveness כדי לבדוק כל provider חיצוני.

12. Packaging, Tooling ו־Project Structure

backend/
├── pyproject.toml

├── src/backend/
│   ├── domain/
│   ├── application/
│   ├── infrastructure/
│   └── api/

pyproject.toml הוא המרכז ל־metadata, build system והגדרות כלים. Lock file מקבע dependency graph שנפתר. Ruff מספק lint/format מהיר, mypy או Pyright בודקים types, pytest מריץ tests ו־pip-audit יכול לזהות vulnerabilities ידועות.

מבנה התיקיות אינו המטרה; כיווני התלות הם החשובים. Domain אינו אמור לייבא adapter של PostgreSQL או framework web. Infrastructure יכולה לממש Protocol שה־application מגדירה.

מבחן שליטה מתקדם: אתה מוכן לעבור ל־Django כאשר אתה מסוגל להסביר למה await אינו thread, למה GIL אינו מונע race, מתי process עדיף, איך file נכתב אטומית, מה ההבדל בין unit ל־integration test, ולמה timeout/retry/idempotency הם שלושה חוזים שונים.
