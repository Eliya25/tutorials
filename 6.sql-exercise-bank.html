SQL Exercise Bank — ‏120 תרגילים ו־8 מעבדות

מסלול מעשי ל־PostgreSQL: מה־SELECT הראשון ועד data modeling, joins, subqueries, window functions, indexes, execution plans, transactions, locking ופתרון בעיות Production.

איך עובדים עם החוברת

  1. קרא רק את הדרישה וכתוב תחילה במילים: מהי שורת התוצאה ומהן הטבלאות הדרושות?
  2. כתוב query בעצמך. אל תבקש מ־AI פתרון לפני ניסיון אמיתי.
  3. בדוק גם edge cases: טבלה ריקה, NULL, כפילויות, לקוח בלי הזמנות והזמנה בלי תשלום.
  4. לפני UPDATE או DELETE, כתוב את אותו WHERE בתוך SELECT. עבוד ב־database מקומי בלבד.
  5. בסוף רשום: מה ציפיתי, מה קיבלתי, למה, ואיך הייתי בודק את זה בקוד Backend.

קצב: 3–4 תרגילים ביום ברמות הראשונות; 1–2 תרגילים עמוקים ברמות המתקדמות. מעבדה יכולה לקחת כמה מפגשים.

רמה 1 — Schema, Types ו־Constraints

1. Database ראשון

צור database נפרד ו־schema בשם store. הגדר אותו ב־search_path של ה־session והסבר database מול schema.

2. טבלת Users

צור users עם identity primary key,‏ email חובה וייחודי, שם חובה ו־created_at עם ברירת מחדל.

3. טיפוסים נכונים

בחר טיפוסים ל־email, מחיר, תאריך לידה, metadata וזמן יצירה. הסבר למה כסף אינו FLOAT ולמה אירועים משתמשים ב־TIMESTAMPTZ.

4. Products ו־CHECK

צור products כך שמחיר ומלאי לא יוכלו להיות שליליים, SKU יהיה ייחודי ו־active יקבל true כברירת מחדל.

5. Foreign Key ראשון

צור categories וקשר product לקטגוריה. החלט האם category יכולה להיות NULL ומה יקרה במחיקת קטגוריה.

6. Orders

צור orders עם FK ל־users ו־status שמוגבל לערכים חוקיים באמצעות CHECK. הסבר יתרון וחיסרון לעומת PostgreSQL enum.

7. Many-to-Many

צור order_items כטבלת קישור. בחר primary key מורכב או surrogate key והגן על quantity ו־discount.

8. Payments

צור payments כך ש־external_id יהיה ייחודי, amount חיובי וסטטוס מוגבל. החלט אם להזמנה מותר יותר מתשלום אחד.

9. ALTER TABLE

הוסף ל־users עמודת phone אופציונלית, הוסף constraint, שנה ברירת מחדל ואז הסר את העמודה. עשה הכול על סביבת התרגול.

10. Seed Data

הכנס נתוני seed שמכסים edge cases. השתמש ב־multi-row INSERT והוכח שכל constraint חוסם לפחות קלט לא חוקי אחד.

שער 1

לפני שממשיכים, אתה צריך להסביר PK, FK, UNIQUE, CHECK, NOT NULL ו־DEFAULT, ולבחור type בלי לנחש.

רמה 2 — SELECT, Filtering ו־NULL

11. SELECT ראשון

הצג את השם והמחיר של כל המוצרים. תן aliases ברורים לעמודות.

12. WHERE

מצא מוצרים פעילים שמחירם מעל סכום נתון. כתוב גרסה עם literal וגרסה שמתאימה ל־parameterized query.

13. AND, OR וסוגריים

מצא מוצר פעיל שהוא זול או חסר במלאי. כתוב query שגוי בלי סוגריים, חזה את ההבדל ואז תקן.

14. BETWEEN ו־IN

מצא הזמנות בטווח תאריכים ובאחד משלושה statuses. בדוק האם גבולות BETWEEN כלולים.

15. LIKE ו־ILIKE

מצא שמות שמכילים טקסט ללא תלות באותיות גדולות. הוסף מוצר שמכיל את התווים % או _ וחפש אותם מילולית.

16. NULL אינו ערך רגיל

מצא users ללא birth_date. נסה תחילה = NULL, תעד את התוצאה ותקן עם התחביר הנכון.

17. Three-Valued Logic

חזה אילו שורות יחזרו מ־WHERE country <> 'IL' כאשר country הוא NULL. כתוב query שכולל גם אותן.

18. COALESCE

הצג country, ואם הוא NULL הצג “לא ידוע”. הסבר האם COALESCE משנה את הנתון או רק את תוצאת השאילתה.

19. DISTINCT

הצג מדינות משלוח ייחודיות. השווה מספר שורות עם ובלי DISTINCT והסבר מתי DISTINCT מסתיר JOIN שגוי.

20. CASE

סווג products ל־cheap, medium, expensive. ודא שכל מחיר נכנס בדיוק לקטגוריה אחת.

רמה 3 — Sorting, Functions ו־CRUD בטוח

21. ORDER BY

מיין מוצרים קודם לפי מחיר יורד ואז לפי name עולה. הוסף שני מוצרים באותו מחיר ובדוק deterministic ordering.

22. LIMIT ו־OFFSET

החזר עמוד שני של 10 מוצרים. שנה נתון בין שתי קריאות והסבר למה offset pagination עלולה לדלג או להכפיל.

23. Keyset Pagination

ממש pagination לפי (created_at,id) במקום OFFSET. כתוב תנאי שמביא את העמוד הבא ללא חפיפות.

24. String Functions

נקה spaces משמות, הצג email באותיות קטנות ובנה label משם ו־id בלי לשנות את הטבלה.

25. Date Functions

מצא הזמנות מהחודש הנוכחי, קבץ זמן ליום והצג את גיל ההזמנה באמצעות interval.

26. INSERT ... RETURNING

צור product והחזר מיד id, sku ו־created_at. הסבר למה Backend צריך RETURNING ולא query נוסף.

27. UPSERT

קלוט מוצר לפי SKU: אם הוא קיים עדכן מחיר ומלאי, אחרת צור אותו. השתמש ב־ON CONFLICT.

28. UPDATE בטוח

העלה מחיר לקטגוריה מסוימת באחוז נתון. לפני השינוי הרץ SELECT זהה בתוך transaction ובצע rollback.

29. DELETE בטוח

מחק reviews ישנות של user ניסוי בלבד. הוכח מראש כמה שורות יימחקו והשתמש ב־RETURNING.

30. Soft Delete

הוסף deleted_at, “מחק” user, וכתוב query שמחזיר רק רשומות חיות. מנה יתרונות וסיכונים לעומת DELETE.

רמה 4 — Aggregations

31. COUNT

השווה COUNT(*),‏ COUNT(country) ו־COUNT(DISTINCT country). הסבר את השפעת NULL.

32. SUM ו־AVG

חשב שווי מלאי כולל ומחיר ממוצע. ודא שכפל אינו נוצר בגלל JOIN.

33. GROUP BY

הצג מספר מוצרים ומחיר ממוצע לכל category_id.

34. HAVING

מצא קטגוריות עם לפחות חמישה מוצרים ומחיר ממוצע מעל סף. הסבר WHERE מול HAVING לפי סדר הביצוע.

35. Conditional Aggregation

הצג בשורה אחת כמה orders נמצאות בכל status באמצעות FILTER או CASE.

36. הכנסה להזמנה

חשב לכל order את הסכום: quantity × unit_price × discount. טפל ב־NULL באופן מפורש.

37. הכנסות יומיות

חשב revenue יומי מתשלומים מוצלחים בלבד. הסבר מדוע אי אפשר לסכום orders ו־payments יחד בלי להבין cardinality.

38. Rollup

הצג הכנסות לפי שנה וחודש וגם subtotal שנתי ו־grand total באמצעות GROUPING SETS או ROLLUP.

39. אחוז מתוך הכול

חשב איזה אחוז מההכנסה מגיע מכל provider בלי query נפרד באפליקציה.

40. באג Aggregation

נתונה שאילתה שבוחרת users.email בלי לקבץ אותו. הסבר למה היא לא חוקית וכתוב שתי כוונות אפשריות עם פתרונות שונים.

שער 2

אתה מוכן ל־JOINs כשאתה יודע להגדיר מה מייצגת כל שורת תוצאה ומדוע GROUP BY לא “מסיר כפילויות”.

רמה 5 — JOINs לעומק

41. INNER JOIN

הצג order id יחד עם שם ו־email של בעל ההזמנה. לפני הכתיבה, זהה מי הטבלה השמאלית ומה תנאי הקשר.

42. LEFT JOIN

הצג את כל המשתמשים ומספר ההזמנות שלהם, כולל משתמשים עם אפס. בדוק מה קורה אם COUNT סופר את העמודה הלא נכונה.

43. תנאי ב־ON מול WHERE

מצא את כל users וההזמנות ששולמו בלבד. כתוב שתי גרסאות שמעבירות את תנאי status בין ON ל־WHERE והסבר מדוע התוצאות שונות.

44. Products שלא נמכרו

מצא products שלא מופיעים בשום order_item באמצעות LEFT JOIN ו־NULL test.

45. Multi-Table JOIN

הצג order, user, items, products ותשלום. קבע מראש מה ה־grain של התוצאה ואילו כפילויות הן אמיתיות.

46. Many-to-Many

הצג את כל המוצרים שרכש user מסוים ואת הכמות הכוללת מכל מוצר.

47. SELF JOIN

הצג category יחד עם שם parent category שלה, כולל קטגוריות root.

48. CROSS JOIN

צור matrix של כל countries מול כל statuses וספור orders בכל תא, כולל אפסים.

49. Join Explosion

חבר orders גם ל־items וגם ל־payments וסכום הכנסות. הוכח כיצד rows מוכפלות ותקן באמצעות pre-aggregation.

50. FULL OUTER JOIN

צור שתי טבלאות staging קטנות והשווה records שנמצאות רק במקור A, רק ב־B ובשניהם.

51. LATERAL JOIN

החזר לכל user את שלוש ההזמנות האחרונות שלו באמצעות LATERAL. השווה לפתרון window function.

52. Join Design Review

קיבלת query עם חמישה JOINs ו־DISTINCT. הסר DISTINCT, זהה את הקשר שיוצר duplication ותקן את המודל או השאילתה.

רמה 6 — Subqueries ו־Set Operations

53. Scalar Subquery

מצא products שמחירם מעל המחיר הממוצע של כלל המוצרים.

54. Correlated Subquery

מצא products שמחירם מעל הממוצע של הקטגוריה שלהם. הסבר כמה פעמים לוגית תת־השאילתה תלויה בשורה החיצונית.

55. EXISTS

מצא users שיש להם לפחות order אחת ששולמה. כתוב עם EXISTS והסבר למה אין צורך להחזיר עמודות מתת־השאילתה.

56. NOT EXISTS

מצא products שמעולם לא נרכשו. השווה ל־LEFT JOIN anti-join.

57. NOT IN ו־NULL

הכנס NULL לסט הבדיקה והראה כיצד NOT IN עלול להחזיר אפס שורות. תקן עם NOT EXISTS.

58. IN מול EXISTS

כתוב את אותה דרישה בשתי הדרכים ובדוק EXPLAIN. אל תקבע מראש איזו מהירה יותר; הסבר תפקיד planner ונתונים.

59. UNION ו־UNION ALL

אחד רשימות emails משני מקורות. הוסף כפילויות והשווה correctness ועלות הסרת כפילויות.

60. INTERSECT

מצא users שגם רכשו וגם כתבו review.

61. EXCEPT

מצא users פעילים שלא ביצעו אף הזמנה בחצי השנה האחרונה.

62. Relational Division

מצא users שרכשו כל מוצר בקטגוריה מסוימת. פתר עם NOT EXISTS כפול.

רמה 7 — CTEs ו־Window Functions

63. CTE לקריאות

פרק query של revenue לפי country לשלבים named. ודא שה־CTE משפר הבנה ולא מסתיר grain.

64. Recursive CTE

החזר עץ category מהשורש, עם depth ו־path מלא. הוסף הגנה רעיונית מפני cycle.

65. ROW_NUMBER

מספר הזמנות לכל user מהחדשה לישנה.

66. Top N per Group

מצא שלושה products הנמכרים ביותר בכל category באמצעות ROW_NUMBER או DENSE_RANK.

67. RANK מול DENSE_RANK

צור ties במכירות והשווה את המספור. קבע איזו פונקציה מתאימה ל־leaderboard.

68. Running Total

חשב revenue מצטבר לפי יום. הגדר במפורש ORDER BY ו־window frame.

69. ROWS מול RANGE

צור כמה תשלומים באותו timestamp והשווה running total עם frames שונים.

70. LAG

חשב שינוי revenue לעומת היום הקודם, גם בסכום וגם באחוזים. טפל ביום הראשון ובחלוקה באפס.

71. LEAD

לכל שינוי status בטבלת history שתיצור, הצג status הבא וכמה זמן נמשך הנוכחי.

72. Sessionization

קבץ events של user ל־sessions כאשר פער מעל 30 דקות מתחיל session חדשה.

73. Rolling Average

חשב moving average של שבעה ימים. הסבר מה קורה בתחילת הטווח כשאין שבע שורות.

74. Cohort בסיסי

קבץ users לפי חודש הרשמה וחשב כמה ביצעו רכישה בחודש 0, 1 ו־2.

רמה 8 — Data Modeling ו־PostgreSQL מתקדם

75. Normalization

קיבלת טבלה אחת עם order, customer ו־product חוזרים. פרק ל־3NF וציין functional dependencies.

76. Denormalization

החלט אם לשמור orders.total_amount. פרט correctness, read performance ודרך שמירה על consistency.

77. Natural מול Surrogate Key

השווה email, SKU ו־identity כ־PK. בחר לכל entity ונמק לפי יציבות, גודל ו־foreign keys.

78. Referential Actions

בחר ON DELETE ל־orders→users, order_items→orders ו־reviews→products. אל תשתמש ב־CASCADE אוטומטית ללא הסבר.

79. JSONB

שמור attributes משתנים של product ב־metadata, חפש לפי key וערך, ועדכן key אחד. הסבר מתי עדיפה עמודה רגילה.

80. Arrays

שמור tags זמניים ב־array, חפש overlap ו־containment. לאחר מכן תכנן מתי לעבור לטבלת relation.

81. Generated Column

צור עמודה מחושבת שמתאימה לחיפוש או display והסבר stored generated column מול חישוב ב־query.

82. View

צור view של order summary עם סכום items וסטטוס payment. בדוק כיצד שינוי בטבלאות משתקף.

83. Materialized View

צור daily_sales materialized view, רענן אותה והשווה freshness מול ביצועים.

84. Full-Text Search

בנה חיפוש PostgreSQL על product name ו־description עם tsvector ו־ranking.

רמה 9 — Indexes ו־EXPLAIN

85. B-tree ראשון

טען נתונים רבים, חפש orders לפי user_id והשווה EXPLAIN ANALYZE לפני ואחרי index.

86. Sequential Scan אינו תמיד רע

חפש ערך שמחזיר אחוז גדול מהטבלה והסבר למה planner עשוי להעדיף seq scan.

87. Composite Index

עצב index לשאילתה WHERE user_id=? AND status=? ORDER BY created_at DESC. בדוק leftmost prefix עם וריאציות.

88. Index Order

השווה indexes על (user_id,status) ועל (status,user_id) לפי שלוש שאילתות שונות.

89. Covering Index

השתמש ב־INCLUDE כדי לאפשר index-only scan. הסבר מדוע visibility map משפיעה ב־PostgreSQL.

90. Partial Index

צור index רק להזמנות pending. הסבר מתי planner יכול ומתי אינו יכול להשתמש בו.

91. Expression Index

אכוף email ייחודי ללא תלות ב־case באמצעות index על expression. בדוק קלט מתנגש.

92. GIN ל־JSONB

צור GIN index ל־metadata והשווה operators ותוכנית ביצוע לפני ואחרי.

93. Selectivity

הסבר מדוע index על boolean לרוב חלש, ואז תכנן partial index אם query נפוץ מצדיק זאת.

94. Statistics

שנה distribution, הרץ ANALYZE ובדוק estimated rows מול actual rows. הסבר כיצד estimates שגויים פוגעים ב־plan.

95. EXPLAIN Reading

ב־plan עם join זהה scan type, join algorithm, estimated/actual rows, loops, cost וזמן. מצא את צוואר הבקבוק.

96. Slow Query Clinic

קח query עם function על indexed column, leading wildcard ו־N+1. אבחן כל בעיה ותן תיקון מדיד.

שער 3

אל תציע index לפי תחושת בטן: כתוב query pattern, cardinality, selectivity, עלות writes והוכחה מ־EXPLAIN ANALYZE.

רמה 10 — Transactions, Locking ו־Concurrency

97. COMMIT ו־ROLLBACK

עדכן שתי טבלאות ב־transaction, גרום לשלב השני להיכשל והוכח ש־rollback מבטל הכול.

98. העברת מלאי

העבר יחידות בין שני warehouses באופן atomic. הגדר invariants שחייבים להישמר.

99. Lost Update

פתח שני sessions שקוראים אותו stock ואז מעדכנים. שחזר lost update ותעד timeline.

100. Atomic UPDATE

מנע overselling באמצעות UPDATE יחיד עם תנאי stock_quantity >= ? ובדוק affected rows.

101. SELECT FOR UPDATE

נעל product ב־session אחד ונסה לעדכן מהשני. בדוק blocking ו־lock timeout.

102. Deadlock

ב־DB ניסוי בלבד, נעל שתי שורות בסדר הפוך בשני sessions ושחזר deadlock. תקן באמצעות lock ordering קבוע.

103. Read Committed

הדגם non-repeatable read ב־isolation ברירת המחדל של PostgreSQL והסבר statement snapshot.

104. Repeatable Read

הרץ את אותו תרחיש תחת Repeatable Read. תעד מה נשאר קבוע ואילו serialization failures אפשריים.

105. Serializable

בנה write skew עסקי והרץ ב־Serializable. הוסף retry loop ברמת pseudocode.

106. Idempotent Payment

תכנן קליטת webhook עם external_id ייחודי כך ש־retry לא ייצור תשלום כפול. שלב constraint ו־transaction.

107. Outbox Pattern

שמור order ואירוע לפרסום באותה transaction. הסבר איזה כשל dual-write נמנע ומה עדיין צריך worker לפתור.

108. Transaction Scope

מצא transaction שמבצעת HTTP call בזמן שהיא מחזיקה lock. עצב מחדש כדי לקצר lock duration בלי לשבור consistency.

רמה 11 — Security, תחזוקה ו־Production

109. SQL Injection

הסבר כיצד string concatenation עם קלט user נשברת, וכתוב parameterized query בסגנון Node $1 ובסגנון Python placeholder.

110. Least Privilege

צור role לקריאה בלבד ו־role לאפליקציה ללא CREATE/DROP. בדוק הרשאות בפועל.

111. Row-Level Security

תכנן policy שמאפשרת tenant לראות רק את השורות שלו. הסבר מדוע session context חייב להיות מהימן.

112. Migration בטוחה

תכנן הוספת עמודה NOT NULL לטבלה גדולה בשיטת expand/backfill/contract בלי downtime.

113. Unique Race

שני requests בודקים email ואז מכניסים. הסבר למה check באפליקציה אינו מספיק ואיך constraint פותר.

114. N+1

API טוען 100 orders ואז items לכל אחת. ספר queries, תקן ב־JOIN או batch query והשווה payload duplication.

115. Connection Pool

חשב תרחיש שבו 20 instances × pool של 20 חורגים מ־max_connections. עצב budget ו־timeouts.

116. Query Timeout

הגדר statement timeout ל־session ניסוי והרץ query איטית מבוקרת. הסבר timeout מול cancellation באפליקציה.

117. Bloat ו־VACUUM

עדכן שורות שוב ושוב, בדוק dead tuples והסבר MVCC, autovacuum ו־VACUUM ANALYZE.

118. Backup אינו Restore

צור dump ל־DB הניסוי ושחזר ל־database חדש. אמת counts ו־constraints; backup נחשב רק אחרי restore test.

119. Incident Investigation

API איטי. בנה סדר בדיקה: pool saturation, active queries, locks, query plan, I/O, CPU ו־recent deploy.

120. Query Review

בחר query אמיתית מפרויקט שלך וכתוב review: correctness, NULL, cardinality, injection, indexes, transaction, pagination ו־observability.

8 מעבדות מסכמות

מעבדה 1 — Store Setup

בנה את כל ה־schema, seed data ו־constraints מאפס. צור ERD והסבר את cardinality של כל קשר. תוצר: קובצי schema.sql, seed.sql ו־README.

מעבדה 2 — Query Challenge

ענה על 20 שאלות עסקיות: top customers, unsold products, repeat buyers, average basket, failed payments ו־retention. תוצר: queries עם expected result ו־edge cases.

מעבדה 3 — JOIN Detective

קבל חמש שאילתות עם missing join condition, filter ב־WHERE, duplicate multiplication ו־wrong COUNT. אתר ותקן כל באג. תוצר: before/after והסבר grain.

מעבדה 4 — Analytics Dashboard

בנה views לדוח revenue יומי, funnel statuses, top products, cohorts ו־moving average. תוצר: queries שמתאימות ל־API dashboard.

מעבדה 5 — Performance Clinic

טען לפחות 100K orders, אסוף EXPLAIN ANALYZE, תכנן indexes ושפר שלוש שאילתות. תוצר: plans לפני/אחרי ומדידה, לא רק טענה.

מעבדה 6 — Checkout Concurrent

ממש transaction ל־checkout: validate stock, decrement atomic, create order/items/payment intent ו־outbox. שחזר שני buyers על הפריט האחרון. תוצר: invariants ו־concurrency test.

מעבדה 7 — Production Migration

שנה מודל address קיים ל־טבלה נפרדת בלי לשבור גרסה ישנה של האפליקציה. תוצר: expand/backfill/dual-read-or-write/contract ו־rollback plan.

מעבדה 8 — SQL Backend Capstone

בנה API קטן ב־Django או Node שמציג catalog, יוצר checkout idempotent ומחזיר order history עם keyset pagination. תוצר: migrations, parameterized queries/ORM SQL logs, tests, indexes ו־README שמגן על כל החלטה.
