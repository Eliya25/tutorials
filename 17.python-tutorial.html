1. איך Python מריצה קוד

CPython, המימוש הנפוץ של Python, קורא את קובץ המקור, מפרק אותו ל־tokens, בונה Abstract Syntax Tree, מקמפל אותו ל־bytecode ואז מריץ את ה־bytecode בתוך virtual machine. לכן Python אינה פשוט “interpreted בלי compilation”: יש compilation, אבל לא ישירות לקוד מכונה כמו C.

python app.py
python -m dis app.py       # הצגת bytecode
python -m module_name      # הרצת module בתוך package context

הקובץ __pycache__ שומר bytecode כדי לחסוך compilation בייבוא עתידי. הוא אינו שומר את תוצאת התוכנית ואינו הופך אותה למהירה כמו binary native.

2. שמות, אובייקטים וטיפוסים

ב־Python משתנה הוא שם שמצביע לאובייקט, לא קופסה עם טיפוס קבוע. בהשמה b = a לא מעתיקים בהכרח את האובייקט; שני השמות יכולים להצביע לאותו אובייקט.

a = [1, 2]
b = a
b.append(3)
assert a == [1, 2, 3]      # אותו list

print(id(a), type(a))
print(a is b)              # identity: True
print(a == b)              # value equality: True
is מול ==: ‏is בודק אם זה אותו אובייקט בזיכרון; == בודק שוויון ערכים. משתמשים ב־is None, אבל לא ב־is 1000 או להשוואת strings.

Python היא dynamically typed אבל strongly typed: הטיפוס נקבע בזמן ריצה, אך השפה לא מחברת שרירותית string ו־integer. Type hints מוסיפים בדיקה סטטית לכלים, לא משנים את מנגנון הריצה.

טיפוסמה חשוב להבין

Falsy values כוללים False,‏ None, אפס ו־collections ריקים. אם אפס הוא ערך חוקי, אל תכתוב if not value כשאתה מתכוון רק ל־None.

5. זרימת בקרה ו־pattern matching

for item in items:
    if item.is_valid():
        process(item)
else:
    print("הלולאה הסתיימה ללא break")

match event:
    case {"type": "user.created", "payload": {"id": user_id}}:
        handle_user(user_id)

6. פונקציות, scope ו־closures

פונקציה היא אובייקט: אפשר להעביר אותה, לשמור אותה ולהחזיר אותה. פרמטרים מועברים בגישת object sharing: הפונקציה מקבלת reference לאותו אובייקט; mutation נראה בחוץ, rebinding מקומי לא.

def create_user(name: str, *, active: bool = True) -> dict[str, object]:
    """הכוכבית מחייבת את active להיות keyword argument."""
    return {"name": name, "active": active}

def make_multiplier(factor: int):
    def multiply(value: int) -> int:
        return value * factor       # closure זוכר את factor
    return multiply
Mutable default trap:
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

Default arguments מחושבים פעם אחת בזמן הגדרת הפונקציה, לא בכל קריאה.

סדר חיפוש שמות הוא LEGB: Local, Enclosing, Global, Builtins. ‏nonlocal משנה שם ב־enclosing scope; ‏global משנה שם module-level, ובדרך כלל dependency injection עדיפה עליו.

7. Iterables, iterators ו־generators

Iterable הוא אובייקט שניתן לבקש ממנו iterator. ‏Iterator מחזיק state ומחזיר פריט הבא באמצעות next(). Generator הוא דרך נוחה ליצור iterator עם yield, ולכן יכול לעבד stream גדול בלי לטעון הכול לזיכרון.

def read_batches(path: str, size: int = 1000):
    batch = []
    with open(path, encoding="utf-8") as file:
        for line in file:
            batch.append(line.rstrip("\n"))
            if len(batch) == size:
                yield batch
                batch = []
    if batch:
        yield batch

Comprehension טובה לטרנספורמציה קצרה. אם יש כמה תנאים, side effects או טיפול בשגיאות—לולאה מפורשת קריאה יותר. Generator expression משתמש בסוגריים ועצלן: sum(x*x for x in values).

8. Exceptions וניקוי משאבים

class InsufficientBalanceError(Exception):
    pass

try:
    debit(account, amount)
except InsufficientBalanceError as exc:
    logger.info("payment rejected", extra={"account_id": account.id})
    raise HTTPException(status_code=409, detail="insufficient balance") from exc
else:
    metrics.increment("payment.success")
finally:
    connection.close()

תופסים את החריגה הצרה שאתה יודע לטפל בה. ‏raise ... from exc שומר causal chain. אל תשתמש ב־except Exception: pass: הוא מסתיר תקלות ומשאיר state לא ברור.

Context manager מרכז acquire/release ומבטיח ניקוי:

from contextlib import contextmanager

@contextmanager
def transaction(db):
    try:
        yield db
        db.commit()
    except Exception:
        db.rollback()
        raise

10. OOP, dataclasses ו־protocols

Class מגדירה התנהגות ומצב. העדף composition כשאין יחס “is-a” אמיתי. ‏@dataclass מתאים ל־data objects ומייצר constructor, repr ושוויון.

from dataclasses import dataclass
from typing import Protocol

@dataclass(frozen=True, slots=True)
class Money:
    amount: int
    currency: str

class PaymentGateway(Protocol):
    def charge(self, payment_id: str, money: Money) -> None: ...

class PaymentService:
    def __init__(self, gateway: PaymentGateway) -> None:
        self.gateway = gateway

Protocol מגדיר interface לפי ההתנהגות הנדרשת (structural typing): implementation אינו חייב לרשת במפורש. זה מאפשר dependency inversion ו־tests פשוטים. ‏frozen=True מונע assignment רגיל אך אינו הופך כל אובייקט פנימי ל־immutable.

11. Decorators ו־descriptors

Decorator מקבל callable ומחזיר callable. Django משתמש ב־decorators ל־permissions, transactions ו־views. חשוב לשמר metadata עם functools.wraps.

from functools import wraps
from time import perf_counter

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(func.__name__, perf_counter() - start)
    return wrapper

Descriptor הוא אובייקט שמגדיר __get__,‏ __set__ או __delete__. ‏Properties, methods ושדות Django ORM נשענים על הפרוטוקול הזה—זו הסיבה ש־user.email יכול להיראות כמו attribute רגיל אך להפעיל לוגיקה.

12. Type hints ו־static analysis

from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")

def first(items: Sequence[T]) -> T:
    if not items:
        raise ValueError("items must not be empty")
    return items[0]

def find_user(user_id: int) -> User | None: ...

העדף abstraction צרה בקלט (Iterable/Sequence) וטיפוס קונקרטי ברור בפלט. ‏Any מכבה בדיקה ומתפשט; השתמש בו רק בגבולות דינמיים. הרץ mypy או pyright ב־CI, אך זכור שה־runtime אינו אוכף hints מעצמו.

בדיקה טובה מתארת behavior, אינה תלויה בסדר, ואינה עושה mock לכל פרט פנימי. Unit tests מהירות ללוגיקה; integration tests בודקות DB/queue אמיתיים; E2E בודקות flow מרכזי. כל bug משמעותי צריך regression test.

כלים חשובים: breakpoint(), logging מובנה, traceback מלא, ‏pytest, coverage, Ruff ו־mypy. Coverage מודד מה רץ—not האם בדקת נכון.

15. Asyncio ו־event loop

Coroutine עוצרת ב־await רק כשהיא מחכה לפעולה async אמיתית. ה־event loop יכול להריץ coroutine אחרת בזמן ההמתנה. זה משפר concurrency של I/O, לא הופך חישוב CPU למהיר.

import asyncio

async def fetch_all(client, urls: list[str]):
    semaphore = asyncio.Semaphore(20)

    async def fetch(url: str):
        async with semaphore:
            return await client.get(url, timeout=5)

    return await asyncio.gather(*(fetch(url) for url in urls))

אל תקרא API סינכרוני חוסם מתוך async view; הוא יחסום את loop כולו. הגבל concurrency, הגדר timeout, טפל ב־cancellation וסגור clients. ‏TaskGroup מספק structured concurrency: חיי המשימות נשארים קשורים ל־scope.

16. Threads, processes וה־GIL

כלימתאים ל־מחיר
asyncioהרבה I/O asyncכל ה־stack צריך לשתף פעולה
threadsI/O סינכרוני או libraries חוסמותshared state, locks ו־races
processesCPU-boundזיכרון נפרד, serialization ו־IPC
job queueעבודה ארוכה/עמידהתשתית, retries ו־idempotency

ב־CPython המסורתי ה־GIL מאפשר thread אחד לבצע Python bytecode בכל רגע בתוך process. הוא אינו מבטל race conditions: פעולות יכולות להשתלב בין bytecodes ו־I/O משחרר את ה־GIL. אל תסמוך על “זה נראה atomic”; השתמש ב־lock או העבר ownership.

17. Memory model וביצועים

CPython משתמש בעיקר ב־reference counting וב־cyclic garbage collector. reference cycle עלול לדרוש GC. ‏__del__ מסבך cleanup; context managers עדיפים למשאבים חיצוניים.

  • מדוד לפני optimization: ‏timeit,‏ cProfile, sampling profiler.
  • בחר algorithm ומבנה נתונים לפני micro-optimization.
  • הימנע מ־N+1 DB queries; latency של הרשת גדולה בדרך כלל מעלות loop קטן.
  • Generators חוסכים זיכרון, אבל אינם תמיד מהירים יותר.
  • slots=True יכול להקטין אובייקטים רבים, במחיר גמישות.

18. Backend ו־Production practices

  • הפרד domain logic מ־HTTP, ORM וספקים חיצוניים.
  • קונפיגורציה מ־environment עם validation בזמן startup.
  • Structured logs עם request/correlation ID—ללא סודות.
  • Timeout לכל I/O חיצוני; retry רק לפעולה בטוחה/אידמפוטנטית, עם backoff ו־jitter.
  • DB transaction קצרה סביב invariant עסקי.
  • Connection pool מוגבל; יותר connections אינם תמיד יותר throughput.
  • Graceful shutdown: הפסק לקבל עבודה, סיים inflight וסגור resources.
  • Health/readiness checks, metrics ו־distributed tracing.
  • נעילת dependencies, scanning ועדכוני אבטחה.
  • Formatter/linter/type-check/tests כחלק מ־CI.
