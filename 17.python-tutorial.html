1. איך Python מריצה קוד

קודם כל: מה קורה כשאנחנו מריצים קובץ?

כשאתה כותב python app.py, המעבד אינו יודע לקרוא ישירות את המילים if,‏ for או print. המעבד מבין הוראות מכונה בינאריות של הארכיטקטורה שלו. לכן צריך רכיב שיקרא את קוד ה־Python, יוודא שהוא בנוי בצורה חוקית ויבצע את המשמעות שלו. ברוב המחשבים הרכיב הזה הוא CPython — המימוש הרשמי והנפוץ ביותר של Python, שנכתב בעיקר בשפת C.

חשוב להפריד בין השפה Python, כלומר החוקים והתחביר, לבין מימוש של Python, כלומר תוכנה שמריצה את החוקים האלה. CPython הוא המימוש הנפוץ, אבל קיימים גם PyPy עם JIT,‏ Jython על JVM ו־MicroPython למערכות קטנות.

שלב 1 — קריאת הטקסט ויצירת Tokens

בהתחלה CPython קורא את התווים בקובץ ומחלק אותם ליחידות בעלות משמעות שנקראות tokens. לדוגמה, בשורה total = price + tax קיימים שם total, סימן השמה, שם price, אופרטור חיבור ושם tax. בשלב הזה עדיין לא מבינים את כל משמעות התוכנית; רק מזהים את אבני הבניין.

שלב 2 — Parsing ו־AST

ה־parser בודק אם סדר ה־tokens מתאים לדקדוק של Python ובונה Abstract Syntax Tree, או AST. זהו עץ שמתאר את המבנה הלוגי של הקוד. למשל, השמה היא node אחד, והחיבור שבצד ימין הוא node פנימי שמכיל שני operands. אם שכחת נקודתיים אחרי if, השגיאה מתגלה כאן כ־SyntaxError, לפני שהתוכנית מתחילה לבצע את הלוגיקה שלך.

# הקוד
total = price + tax

# מודל מפושט של העץ
Assignment
├── target: total
└── value: Add
    ├── price
    └── tax

שלב 3 — Compilation ל־Bytecode

לאחר מכן CPython מקמפל את ה־AST ל־bytecode. אלה הוראות עבור המכונה הווירטואלית של Python, לא הוראות ישירות למעבד. הוראות כמו “טען שם”, “בצע חיבור” ו־“שמור שם” כלליות ולכן אותו bytecode יכול לרוץ על מערכות שונות כל עוד מותקן עליהן interpreter מתאים.

שלב 4 — Python Virtual Machine

לולאת הריצה של CPython קוראת כל הוראת bytecode ומבצעת אותה. אם ההוראה היא חיבור, Python בודקת בזמן ריצה מהם סוגי האובייקטים ומה משמעות החיבור עבורם. זאת אחת הסיבות ש־Python גמישה, אך בדרך כלל איטית יותר מקוד C שעבר compilation לקוד מכונה מותאם מראש.

python app.py
python -m dis app.py       # הצגת bytecode
python -m module_name      # הרצת module בתוך package context

בתיקיית __pycache__ נשמר לעיתים bytecode של modules שיובאו, כדי שלא יהיה צורך לקמפל אותם מחדש בכל הרצה אם המקור לא השתנה. זהו cache של שלב ההכנה בלבד: הוא אינו שומר תוצאות עסקיות ואינו הופך את הקוד ל־native binary.

המודל שצריך לזכור: Source code → Tokens → AST → Bytecode → Python Virtual Machine → פעולות על אובייקטים. לא צריך לזכור כל הוראת bytecode; כן צריך להבין ששגיאת תחביר מתרחשת לפני הריצה, בעוד TypeError יכול להתרחש רק כשהשורה מבוצעת.

2. שמות, אובייקטים וטיפוסים

המודל החשוב ביותר בשפה

כמעט כל דבר ב־Python הוא אובייקט: מספר, מחרוזת, list, פונקציה, class ואפילו module. אובייקט כולל לפחות זהות, טיפוס וערך. הזהות מבדילה בינו לבין אובייקטים אחרים; הטיפוס קובע אילו פעולות הוא תומך; והערך הוא המידע שהוא מייצג.

משתנה ב־Python אינו קופסה שמכילה את הערך ואינו “בעל טיפוס” קבוע. הוא שם שנקשר לאובייקט. השורה age = 25 יוצרת או מאתרת אובייקט integer שערכו 25 וקושרת אליו את השם age. מאוחר יותר אפשר לקשור את אותו שם לאובייקט מסוג אחר:

age = 25          # age מצביע כרגע ל-int
age = "twenty"    # עכשיו אותו שם מצביע ל-str

האובייקט עצמו עדיין בעל טיפוס ברור; רק השם יכול לעבור בין אובייקטים. זו המשמעות של dynamic typing: הקישור והבדיקה נעשים בזמן ריצה.

Assignment אינו בהכרח Copy

בהשמה b = a, Python קושרת גם את b לאותו אובייקט. היא לא מבטיחה ליצור עותק. אם האובייקט mutable ואחד השמות משנה אותו, השינוי נראה דרך כל שם שמצביע אליו.

a = [1, 2]
b = a
b.append(3)
assert a == [1, 2, 3]      # אותו list

print(id(a), type(a))
print(a is b)              # identity: True
print(a == b)              # value equality: True

Mutation מול Rebinding

Mutation משנה את תוכן האובייקט הקיים, למשל append על list. ‏Rebinding קושר שם לאובייקט אחר, למשל a = [9]. Rebinding של a לא משנה לאן b מצביע.

a = [1, 2]
b = a
a.append(3)       # mutation: שניהם רואים [1, 2, 3]
a = [9]           # rebinding: רק a עבר לאובייקט אחר
print(a)          # [9]
print(b)          # [1, 2, 3]
is מול ==: ‏is בודק identity — האם שני השמות מצביעים ממש לאותו אובייקט. ‏== מפעיל השוואת ערכים שהטיפוס מגדיר. שני lists נפרדים יכולים להיות שווים ב־== אך שונים ב־is. משתמשים ב־is None, מפני ש־None הוא singleton, ולא ב־is להשוואת מספרים או strings.

Strongly Typed

Python היא גם strongly typed: היא אינה מבצעת כל המרה אפשרית בשקט. ‏"5" + 2 יגרום ל־TypeError, כי חיבור string ו־integer אינו מוגדר. עליך לבחור אם לבצע int("5") + 2 או "5" + str(2). זה מונע פרשנות שרירותית של הנתונים.

Type Hints אינם משנים את Runtime

def double(value: int) -> int:
    return value * 2

double("ha")  # Python עצמה תריץ ותחזיר "haha"

ה־hint אומר לכלים ולמפתחים מה החוזה הצפוי, אך CPython לא אוכפת אותו אוטומטית. mypy או Pyright יכולים לזהות את הקריאה השגויה לפני הרצה; validation של קלט חיצוני עדיין חייב לקרות בזמן ריצה.

3. מספרים, מחרוזות ו־None

Integer ופעולות חשבון

int מייצג מספר שלם חיובי, שלילי או אפס. בניגוד לטיפוס 32-bit בשפות מסוימות, integer של Python יכול לגדול כל עוד יש זיכרון, במחיר של יותר הקצאות ועבודה. האופרטור / מחזיר float, ‏// מבצע floor division, ‏% מחזיר שארית ו־** חזקה.

7 / 2       # 3.5
7 // 2      # 3
7 % 2       # 1
2 ** 10     # 1024
divmod(7, 2)  # (3, 1)

Float ולמה כסף הוא מקרה מיוחד

רוב ערכי float נשמרים לפי IEEE-754 בבסיס בינארי. מספר עשרוני פשוט כמו 0.1 אינו ניתן לייצוג בינארי סופי, ולכן נשמר קירוב. זאת אינה “תקלה של Python”; זו תכונה של floating point ברוב השפות והמעבדים.

0.1 + 0.2 == 0.3       # False
print(0.1 + 0.2)       # 0.30000000000000004

למדידות מדעיות משווים לעיתים עם tolerance. לכסף משתמשים ב־integer של אגורות או ב־Decimal, כאשר יוצרים אותו מ־string כדי לא להכניס מראש את שגיאת ה־float.

טיפוסמה חשוב להבין
intמספר שלם בגודל דינמי; אין overflow רגיל של 32-bit.
floatIEEE-754; אינו מדויק לכסף. לכסף השתמש ב־Decimal.
strרצף Unicode immutable.
bytesבתים בינאריים; צריך encoding כדי להמיר ל־str.
Noneהיעדר ערך; singleton שנבדק עם is None.
from decimal import Decimal
price = Decimal("19.90")     # לא Decimal(19.90)

text = "שלום"
payload = text.encode("utf-8")
assert payload.decode("utf-8") == text

name = "Eliya"
message = f"Hello {name}"

Strings, Unicode ו־Bytes

str הוא טקסט Unicode; ‏bytes הוא רצף של ערכים בינאריים בין 0 ל־255. רשת, קובץ ותהליך אחר מעבירים bytes. ‏Encoding הוא החוק שממיר תווים לבתים, ו־decoding הוא הכיוון ההפוך. UTF-8 הוא encoding נפוץ שתומך בעברית ובשפות נוספות.

String הוא immutable: פעולות כמו upper או replace מחזירות string חדש. הדבר מאפשר לשתף strings בבטחה ולהשתמש בהם כ־dictionary keys.

name = "  Eliya Cohen  "
clean = name.strip().lower()
first, last = clean.split(maxsplit=1)
slug = clean.replace(" ", "-")
print(f"{first=}, {last=}, {slug=}")

None ו־Truthiness

None מציין בדרך כלל “אין ערך”. הוא שונה מאפס, string ריק או list ריקה—אלה ערכים קיימים שעשויים להיות תקינים. בבדיקה בוליאנית, ‏False,‏ None, אפס ו־collections ריקים הם falsy; רוב הערכים האחרים truthy.

def display_count(count: int | None) -> str:
    if count is None:
        return "not measured"
    return str(count)       # גם 0 הוא מדידה חוקית

לכן if not count היה מערבב בין “לא נמדד” לבין “נמדד אפס”. לפני בדיקת truthiness שאל מה בדיוק החוזה העסקי.

4. Collections ו־mutability

Collection מחזיק כמה ערכים. הבחירה אינה רק עניין תחבירי: היא קובעת אם יש סדר, אם מותרות כפילויות, איך מבצעים lookup, האם אפשר לשנות את המבנה ומהי עלות הפעולות.

מבנהתכונותשימוש טיפוסי
listמסודר, mutable, כפילויותרצף שמשתנה
tupleמסודר, immutablerecord קטן או key אם כל איבריו hashable
dictמיפוי key→value, שומר insertion orderlookup ומודלים דינמיים
setערכים ייחודיים, membership ממוצע O(1)deduplication וחיתוכים

List — רצף דינמי

List תומכת בגישה לפי index, slicing, הוספה ומחיקה. גישה לפי index היא O(1) בממוצע; חיפוש ערך הוא O(n); הוספה לסוף amortized O(1); והכנסה בתחילת הרשימה O(n), כי צריך להזיז את האיברים. עבור queue השתמש ב־collections.deque במקום pop(0).

numbers = [10, 20, 30]
numbers.append(40)
numbers.extend([50, 60])
last = numbers.pop()
middle = numbers[1:4]      # list חדשה
reversed_copy = numbers[::-1]

Tuple — מבנה קבוע

Tuple אינה ניתנת להוספה או הסרה לאחר יצירה. היא מתאימה לקבוצה קטנה של ערכים ששייכים יחד או לתוצאה מרובת ערכים. Immutable מתייחס ל־tuple עצמה; אם היא מחזיקה list, הרשימה הפנימית עדיין mutable.

Dictionary — Hash Table

Dictionary ממפה key ייחודי לערך ומשתמשת ב־hash כדי להגיע אליו בממוצע O(1). Key חייב להיות hashable: בדרך כלל immutable ובעל hash יציב. לכן list לא יכולה לשמש key, אבל string או tuple של ערכים hashable כן.

user = {"id": 42, "name": "Eliya"}
name = user["name"]                 # KeyError אם חסר
role = user.get("role", "user")     # fallback
user["active"] = True

for key, value in user.items():
    print(key, value)

Set — ייחודיות ופעולות קבוצות

requested = {"python", "django", "sql"}
completed = {"python", "git"}
remaining = requested - completed
shared = requested & completed
all_topics = requested | completed

Set טובה לבדיקת membership ולהסרת כפילויות כשסדר אינו העיקר. אם אתה זקוק לסדר המקורי, אפשר להשתמש ב־dict.fromkeys(items) או לעבור עם set עזר.

users_by_id = {user["id"]: user for user in users}
active_names = {u["name"] for u in users if u["active"]}
first, *middle, last = [1, 2, 3, 4]

Shallow Copy מול Deep Copy

Shallow copy יוצרת container חיצוני חדש אבל משאירה references לאותם אובייקטים פנימיים. לכן mutation של list פנימית יופיע בשני המבנים. ‏deepcopy מנסה להעתיק רקורסיבית את כל גרף האובייקטים, אך יכולה להיות יקרה ולהעתיק דברים שלא רצית. לעיתים עדיף ליצור במפורש object חדש מהשדות הנדרשים.

matrix = [[0] * 3 for _ in range(3)]  # שלוש שורות שונות
# [[0] * 3] * 3 היה יוצר שלוש הפניות לאותה שורה

original = {"db": {"host": "prod"}}
shallow = original.copy()
shallow["db"]["host"] = "test"
print(original["db"]["host"])  # test

5. זרימת בקרה ו־pattern matching

Conditions

if,‏ elif ו־else בוחרים איזה block להריץ. ב־Python ההזחה היא חלק מהתחביר, בדרך כלל ארבעה spaces. השוואות יכולות להתחבר, ו־and/or מבצעים short-circuit: הצד השני אינו מחושב אם התוצאה כבר ידועה.

if 18 <= age < 67 and user.is_active:
    allow_access()
elif not user.is_active:
    explain_inactive_account()
else:
    deny_access()

and ו־or מחזירים אחד מה־operands, לא תמיד boolean. הביטוי name = supplied_name or "Guest" משתמש ב־fallback לכל ערך falsy, כולל string ריק; ודא שזה אכן החוזה הרצוי.

Loops

for עובר על iterable ישירות—אין צורך לנהל index אם אינך צריך אותו. ‏enumerate מספק index, ‏zip מחבר iterables ו־range יוצר רצף מספרים עצלן. ‏break מסיים לולאה, ‏continue עובר לאיטרציה הבאה.

for item in items:
    if item.is_valid():
        process(item)
else:
    print("הלולאה הסתיימה ללא break")

match event:
    case {"type": "user.created", "payload": {"id": user_id}}:
        handle_user(user_id)
    case {"type": event_type}:
        raise ValueError(f"unsupported event: {event_type}")

ה־else של loop רץ אם הלולאה הסתיימה בלי break. ‏Structural pattern matching אינו switch פשוט; הוא יכול לפרק מבני נתונים ולבצע guard.

מתי להשתמש ב־match?

match מתאים כשמבנה הנתון קובע את הפעולה, למשל events מסוגים שונים. הוא לא מחליף polymorphism או dictionary dispatch בכל מקום. Pattern יכול גם bind שמות, ולכן צריך להיזהר ש־case כללי לא יתפוס לפני case ספציפי.

6. פונקציות, scope ו־closures

למה בכלל פונקציות?

פונקציה נותנת שם ליחידת התנהגות, מקבלת inputs ומחזירה output. היא מאפשרת לפרק בעיה, למנוע כפילות ולבדוק לוגיקה בנפרד. פונקציה טובה בדרך כלל עושה דבר אחד ברור והשם שלה מתאר את התוצאה או הפעולה.

def calculate_total(price, quantity):
    total = price * quantity
    return total

result = calculate_total(19.90, 3)

price ו־quantity הם parameters בהגדרה; ‏19.90 ו־3 הם arguments בקריאה. ‏return מסיים את הפונקציה ומחזיר ערך. אם אין return מפורש, מוחזר None.

Positional, Keyword ו־Default Arguments

def create_user(name: str, *, active: bool = True) -> dict[str, object]:
    """הכוכבית מחייבת את active להיות keyword argument."""
    return {"name": name, "active": active}

def make_multiplier(factor: int):
    def multiply(value: int) -> int:
        return value * factor       # closure זוכר את factor
    return multiply

Argument positional משויך לפי המיקום. Keyword משויך לפי השם ומשפר קריאות. Default מאפשר להשמיט argument. כוכבית יחידה בהגדרה אומרת שהפרמטרים אחריה keyword-only, שימושי כדי שקריאה כמו create_user("Eliya", active=False) תהיה ברורה.

def connect(host, port=5432, *, timeout=5, ssl=True):
    ...

connect("db.internal")
connect("db.internal", 5433, timeout=2, ssl=False)

*args ו־**kwargs

*args אוסף arguments positional נוספים ל־tuple; ‏**kwargs אוסף keyword arguments נוספים ל־dict. הם שימושיים ב־wrappers וב־APIs גמישים, אך שימוש יתר מסתיר את החוזה ומחליש type checking.

איך Arguments עוברים לפונקציה?

Python מעבירה references לאובייקטים בגישה שמכונה call by sharing. הפונקציה מקבלת שם מקומי שמצביע לאותו אובייקט. Mutation נראה לקורא; rebinding של השם המקומי לא משנה את השם של הקורא.

def mutate(items):
    items.append("new")     # משנה את אותו list

def rebind(items):
    items = ["other"]        # משנה רק את השם המקומי

values = []
mutate(values)
rebind(values)
print(values)               # ["new"]
Mutable default trap:
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

Default arguments מחושבים פעם אחת בזמן הגדרת הפונקציה, לא בכל קריאה.

Scope ו־LEGB

שם מקומי קיים בתוך קריאת פונקציה. Python מחפשת שם לפי LEGB: ‏Local, אחר כך Enclosing בפונקציה עוטפת, אחר כך Global ברמת module ולבסוף Builtins כמו len. השמה בתוך פונקציה יוצרת שם מקומי כברירת מחדל.

nonlocal מאפשר rebinding של שם ב־enclosing function; ‏global עושה זאת לשם ברמת module. שניהם חוקיים, אך state גלובלי מקשה על tests ו־concurrency, ולכן בדרך כלל מעבירים dependencies במפורש.

Functions הן Objects ו־Closures

פונקציה ב־Python היא אובייקט: ניתן לשמור אותה ב־list, להעביר אותה כ־argument ולהחזיר אותה. Closure היא פונקציה פנימית ששומרת גישה לשמות מה־scope העוטף גם אחרי שהפונקציה החיצונית הסתיימה. בדוגמת make_multiplier, כל פונקציה מוחזרת זוכרת factor משלה.

בדיקת הבנה: לפני מעבר לפרק הבא, ודא שאתה מסוגל להסביר למה שינוי list בתוך פונקציה יכול להופיע בחוץ, אבל השורה items = [] לא מחליפה את המשתנה של הקורא.

7. Iterables, iterators ו־generators

הבעיה שהפרוטוקול פותר

לולאת for צריכה לדעת לעבור על list, tuple, file, set, dictionary ו־generator אף שהם בנויים אחרת. במקום לכתוב לולאה מיוחדת לכל טיפוס, Python מגדירה iterator protocol: חוזה קטן שכל מבנה יכול לממש.

Iterable הוא אובייקט שאפשר לבקש ממנו iterator באמצעות iter(). ‏Iterator הוא אובייקט שמחזיק את מיקום ההתקדמות ומחזיר את הפריט הבא באמצעות next(). כשהפריטים נגמרים, הוא מעלה StopIteration; לולאת for מטפלת בכך מאחורי הקלעים.

numbers = [10, 20, 30]
iterator = iter(numbers)

print(next(iterator))  # 10
print(next(iterator))  # 20
print(next(iterator))  # 30
# next(iterator) יעלה StopIteration

Iterable יכול ליצור iterator חדש בכל קריאה ולכן אפשר בדרך כלל לעבור עליו שוב. Iterator עצמו הוא stateful ולעיתים חד־פעמי: אחרי שנצרך, הוא נשאר בסוף.

Generator ו־yield

פונקציה שמכילה yield אינה מריצה מיד את כל הגוף. הקריאה אליה יוצרת generator object. בכל next(), הקוד ממשיך עד yield הבא, מחזיר ערך ומשהה את frame של הפונקציה—כולל משתנים מקומיים ומיקום ביצוע.

def read_batches(path: str, size: int = 1000):
    batch = []
    with open(path, encoding="utf-8") as file:
        for line in file:
            batch.append(line.rstrip("\n"))
            if len(batch) == size:
                yield batch
                batch = []
    if batch:
        yield batch

היתרון הוא lazy evaluation: אפשר לקרוא קובץ של עשרות GB בקבוצות קטנות. המחיר הוא שהנתונים מחושבים בזמן הצריכה, שגיאות עשויות להופיע מאוחר, ו־generator שנצרך לא ניתן “להחזיר להתחלה” בלי ליצור חדש.

Comprehensions

squares = [number ** 2 for number in numbers]
even_squares = [number ** 2 for number in numbers if number % 2 == 0]
by_id = {user.id: user for user in users}
unique_domains = {email.split("@", 1)[1] for email in emails}

# generator expression — לא בונה list מראש
total = sum(number ** 2 for number in numbers)

Comprehension טובה לטרנספורמציה קצרה וברורה. אם יש כמה branches, טיפול בחריגות או side effects, לולאה רגילה תהיה קריאה וניתנת לדיבוג יותר.

8. Exceptions וניקוי משאבים

מהי Exception?

Exception היא אובייקט שמתאר מצב שבו המסלול הרגיל אינו יכול להמשיך. כשמבצעים raise, Python עוצרת את ה־flow הנוכחי ומתחילה stack unwinding: היא יוצאת מקריאות הפונקציות עד שהיא מוצאת except מתאים. אם אין handler, התהליך מציג traceback ומסיים את הפעולה.

def parse_age(raw: str) -> int:
    try:
        age = int(raw)
    except ValueError as exc:
        raise ValueError("age must be an integer") from exc

    if age < 0:
        raise ValueError("age must not be negative")
    return age

ה־traceback הוא שרשרת הקריאות שהובילה לשגיאה. אל תמהר למחוק אותו; הוא אחד הכלים החשובים ביותר בדיבוג. ‏raise ... from exc מתרגם exception משכבת infrastructure לחוזה של השכבה שלך ושומר את הסיבה המקורית.

ארבעת חלקי try

class InsufficientBalanceError(Exception):
    pass

try:
    debit(account, amount)
except InsufficientBalanceError as exc:
    logger.info("payment rejected", extra={"account_id": account.id})
    raise HTTPException(status_code=409, detail="insufficient balance") from exc
else:
    metrics.increment("payment.success")
finally:
    connection.close()
  • try מכיל רק את הקוד שעלול להיכשל בצורה שאתה מטפל בה.
  • except רץ עבור exception מתאים.
  • else רץ אם לא נזרקה exception; הוא מונע מ־except לתפוס בטעות שגיאה מקוד ההמשך.
  • finally רץ כמעט תמיד ומשמש לניקוי, גם כשיש return או exception.

תפוס את החריגה הצרה שאתה יודע לטפל בה. ‏except Exception: pass מסתיר תקלות, מאבד traceback ועלול להשאיר state חלקי. אם אינך יכול לפתור את השגיאה, הוסף context ואז re-raise.

Context Manager

משאבים כמו file, lock או database transaction צריכים להיסגר גם כשמשהו נכשל. Context manager מגדיר פעולת כניסה ויציאה, וה־with מבטיח שהיציאה תקרה.

from contextlib import contextmanager

@contextmanager
def transaction(db):
    try:
        yield db
        db.commit()
    except Exception:
        db.rollback()
        raise

הערך שאחרי yield נמסר ל־as; הקוד לפניו הוא acquire והקוד אחריו cleanup. אפשר לממש אותו גם עם __enter__/__exit__. החזרת True מ־__exit__ בולעת exception, ולכן עושים זאת רק בכוונה ברורה.

9. Modules, packages וסביבות

למה לחלק קוד?

ככל שתוכנית גדלה, קובץ יחיד הופך קשה להבנה ולבדיקה. Module הוא בדרך כלל קובץ .py שמרכז שמות בעלי אחריות משותפת. Package הוא תיקייה של modules שמספקת namespace ומבנה לפרויקט.

taskflow/
├── pyproject.toml
├── src/
│   └── taskflow/
│       ├── __init__.py
│       ├── domain.py
│       ├── services.py
│       └── cli.py
└── tests/
    └── test_services.py

מה import עושה?

בפעם הראשונה ש־module מיובא, Python מאתרת אותו לפי sys.path, יוצרת module object ומריצה את הקוד העליון שלו. התוצאה נשמרת ב־sys.modules, ולכן import נוסף באותו process בדרך כלל מחזיר את אותו object בלי להריץ מחדש.

מכאן נובעות שתי תופעות: קוד top-level בעל side effects רץ בזמן import, ו־circular imports יכולים לראות module שעדיין לא סיים initialization. שמור top-level להגדרות, constants ויצירת classes/functions; העבר חיבורי רשת ו־startup לפונקציה מפורשת.

Absolute ו־Relative Imports

# absolute — בדרך כלל ברור יותר
from taskflow.domain import Task

# relative — בתוך אותו package
from .domain import Task

הרצה עם python -m taskflow.cli שומרת package context, בעוד הרצת קובץ פנימי ישירות עלולה לשבור imports. זו הסיבה ש־-m חשוב.

Virtual Environment

שני פרויקטים יכולים להזדקק לגרסאות שונות של אותה ספרייה. Virtual environment יוצרת סביבת interpreter ו־site-packages מבודדת לפרויקט. היא אינה container ואינה VM; היא בעיקר מבודדת dependencies של Python.

python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install django pytest ruff mypy

if __name__ == "__main__" מבדיל בין הרצה ישירה לבין import. בפרויקט מודרני pyproject.toml מתאר metadata, dependencies והגדרות כלים. Lock file מבטיח שהצוות ו־CI מתקינים אותן גרסאות בפועל. כלים כמו uv יכולים לנהל environment, lock והתקנה במהירות, אך חשוב להבין את העקרונות גם אם הכלי משתנה.

10. OOP, dataclasses ו־protocols

Object ו־Class

Class היא תבנית שמגדירה איזה state והתנהגות יהיו לאובייקטים. Instance הוא אובייקט שנוצר מה־class. ‏__init__ מאתחלת instance שכבר נוצר, ו־self הוא reference ל־instance שעליו method פועלת.

class BankAccount:
    bank_name = "Example Bank"          # class attribute

    def __init__(self, owner: str, balance: int = 0):
        if balance < 0:
            raise ValueError("balance cannot be negative")
        self.owner = owner               # instance attributes
        self._balance = balance

    @property
    def balance(self) -> int:
        return self._balance

    def deposit(self, amount: int) -> None:
        if amount <= 0:
            raise ValueError("amount must be positive")
        self._balance += amount

Class attribute משותף דרך ה־class; instance attribute שייך לכל instance. חיפוש attribute מתחיל ב־instance ואז ממשיך ל־class ולמחלקות בסיס לפי Method Resolution Order. קו תחתון בשם כמו _balance הוא convention של “פנימי”, לא חסימה אבטחתית.

Encapsulation ו־Properties

Encapsulation פירושה לשמור invariant מאחורי API ברור. ‏@property מאפשר לקרוא method כאילו היה attribute, ו־setter יכול לבצע validation. אל תיצור getters/setters אוטומטיים לכל שדה; השתמש בהם כשיש behavior או חוזה שחשוב להגן עליו.

Inheritance מול Composition

Inheritance מתאימה ליחס אמיתי של “הוא סוג של” ולחוזה substitution תקין. Composition מחברת אובייקטים לפי “יש לו” ומאפשרת להחליף רכיב בלי היררכיה עמוקה. בשירותי Backend, composition ו־dependency injection בדרך כלל גמישות יותר.

Dataclasses

כאשר class בעיקר מחזיקה נתונים, @dataclass מייצרת __init__,‏ __repr__ ו־__eq__. אפשר להוסיף validation ב־__post_init__.

from dataclasses import dataclass
from typing import Protocol

@dataclass(frozen=True, slots=True)
class Money:
    amount: int
    currency: str

class PaymentGateway(Protocol):
    def charge(self, payment_id: str, money: Money) -> None: ...

class PaymentService:
    def __init__(self, gateway: PaymentGateway) -> None:
        self.gateway = gateway

frozen=True מונע assignment רגיל לשדות אך אינו מקפיא objects mutable שנמצאים בפנים. ‏slots=True מצמצם בדרך כלל זיכרון ומונע attributes מקריים, אך משנה חלק מגמישות ה־object.

Protocol ו־Duck Typing

Python פועלת הרבה לפי duck typing: אם object מספק את ההתנהגות הנדרשת, אין חובה שיירש class מסוים. ‏Protocol נותן לכלי type checking דרך לתאר את החוזה הזה. מימוש gateway אמיתי ו־fake לבדיקה יכולים להתאים לאותו Protocol בלי inheritance מפורשת.

11. Decorators ו־descriptors

Functions מסדר גבוה

לפני decorator צריך להבין שפונקציה היא object. פונקציה יכולה לקבל פונקציה ולהחזיר פונקציה—זאת higher-order function. Decorator הוא תחביר נוח להחלפת function באחרת בזמן ההגדרה.

def logged(func):
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

# שקול רעיונית ל:
# add = logged(add)

Django משתמשת ב־decorators להרשאות, transactions ו־views. ה־wrapper חייב להחזיר את תוצאת הפונקציה ולשמר את metadata שלה.

from functools import wraps
from time import perf_counter

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(func.__name__, perf_counter() - start)
    return wrapper

Decorator עם Arguments

כאשר כותבים @retry(max_attempts=3), הפונקציה החיצונית מקבלת configuration ומחזירה decorator; ה־decorator מקבל function ומחזיר wrapper. אלה שלוש שכבות, ולכן קל להתבלבל. כתוב שמות ברורים ו־tests ל־return, exception ו־metadata.

Descriptors

Descriptor הוא object שמגדיר לפחות אחת מהמתודות __get__,‏ __set__ או __delete__. כש־descriptor נמצא על class, גישה ל־attribute יכולה להפעיל את הלוגיקה שלו במקום להחזיר value פשוט.

Functions על class הן descriptors: זו הסיבה ש־account.deposit מקבלת אוטומטית את account כ־self. גם property ושדות Django ORM משתמשים ברעיון. ‏user.email נראה כמו attribute רגיל, אך descriptor יכול לבצע validation, tracking או גישה ל־state אחר.

סדר לימוד: Decorators שימושיים ביום־יום. Descriptors הם מנגנון פנימי מתקדם; חשוב להבין מה הם מסבירים, אך אין צורך לכתוב descriptor מותאם לפני שאתה שולט ב־classes ו־properties.

12. Type hints ו־static analysis

איזו בעיה Type Hints פותרות?

במערכת גדולה, שם כמו data לא אומר מה מותר להעביר ומה מוחזר. Type hint מתעדת חוזה בצורה שכלים יכולים לבדוק לפני הריצה, IDE יכול להציע השלמה, ו־reviewer יכול להבין בלי לעקוב אחרי כל מסלול.

def calculate_total(prices: list[float]) -> float:
    return sum(prices)

def load_user(user_id: int) -> User | None:
    ...

User | None מכריח את הקורא להתמודד עם האפשרות שאין משתמש. לאחר בדיקת if user is None, type checker מבצע narrowing ויודע שבמסלול האחר זה User.

Collections Abstractions

אם פונקציה רק עוברת על values, היא אינה צריכה לדרוש list. ‏Iterable[T] מקבל list, tuple או generator. אם צריך len ו־index, ‏Sequence[T] מדויק יותר. קבל interface מינימלי שמתאים להתנהגות.

from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")

def first(items: Sequence[T]) -> T:
    if not items:
        raise ValueError("items must not be empty")
    return items[0]

def find_user(user_id: int) -> User | None: ...

Generics ו־TypeVar

בדוגמת first, ‏TypeVar אומר שהטיפוס המוחזר זהה לטיפוס האיברים: Sequence של User מחזירה User, ושל str מחזירה str. בלי generic היינו מאבדים את הקשר הזה.

Any, object ו־Unknown Data

Any אומר לכלי “אל תבדוק אותי” ומתפשט לקוד שקורא לו. ‏object אומר “יכול להיות כל object, ולכן לפני פעולה צריך לבדוק/narrow”. בגבול JSON חיצוני, type hint אינה validation; צריך parser או schema שמוודא את runtime data.

הרץ mypy או Pyright ב־CI. התחל strict בקוד חדש או החמר בהדרגה. אל תעקוף שגיאות עם casts ו־ignores לפני שהבנת אם הכלי גילה bug אמיתי.

path.parent.mkdir(parents=True, exist_ok=True)
payload = {"version": 1, "users": []}

def test_transfer_moves_money(account_factory):
    source = account_factory(balance=100)

    transfer(source, target, 30)

    assert source.balance == 70

בדיקה טובה מתארת behavior, אינה תלויה בסדר, ואינה עושה mock לכל פרט פנימי. Unit tests מהירות ללוגיקה; integration tests בודקות DB/queue אמיתיים; E2E בודקות flow מרכזי. כל bug משמעותי צריך regression test.

15. Asyncio ו־event loop

Coroutine עוצרת ב־await רק כשהיא מחכה לפעולה async אמיתית. ה־event loop יכול להריץ coroutine אחרת בזמן ההמתנה. זה משפר concurrency של I/O, לא הופך חישוב CPU למהיר.

import asyncio

async def fetch_all(client, urls: list[str]):
    semaphore = asyncio.Semaphore(20)

    async def fetch(url: str):
        async with semaphore:
            return await client.get(url, timeout=5)

    return await asyncio.gather(*(fetch(url) for url in urls))

אל תקרא API סינכרוני חוסם מתוך async view; הוא יחסום את loop כולו. הגבל concurrency, הגדר timeout, טפל ב־cancellation וסגור clients. ‏TaskGroup מספק structured concurrency: חיי המשימות נשארים קשורים ל־scope.

16. Threads, processes וה־GIL

כלימתאים ל־מחיר
asyncioהרבה I/O asyncכל ה־stack צריך לשתף פעולה
threadsI/O סינכרוני או libraries חוסמותshared state, locks ו־races
processesCPU-boundזיכרון נפרד, serialization ו־IPC
job queueעבודה ארוכה/עמידהתשתית, retries ו־idempotency

ב־CPython המסורתי ה־GIL מאפשר thread אחד לבצע Python bytecode בכל רגע בתוך process. הוא אינו מבטל race conditions: פעולות יכולות להשתלב בין bytecodes ו־I/O משחרר את ה־GIL. אל תסמוך על “זה נראה atomic”; השתמש ב־lock או העבר ownership.

17. Memory model וביצועים

CPython משתמש בעיקר ב־reference counting וב־cyclic garbage collector. reference cycle עלול לדרוש GC. ‏__del__ מסבך cleanup; context managers עדיפים למשאבים חיצוניים.

  • מדוד לפני optimization: ‏timeit,‏ cProfile, sampling profiler.
  • בחר algorithm ומבנה נתונים לפני micro-optimization.
  • הימנע מ־N+1 DB queries; latency של הרשת גדולה בדרך כלל מעלות loop קטן.
  • Generators חוסכים זיכרון, אבל אינם תמיד מהירים יותר.
  • slots=True יכול להקטין אובייקטים רבים, במחיר גמישות.

18. Backend ו־Production practices

  • הפרד domain logic מ־HTTP, ORM וספקים חיצוניים.
  • קונפיגורציה מ־environment עם validation בזמן startup.
  • Structured logs עם request/correlation ID—ללא סודות.
  • Timeout לכל I/O חיצוני; retry רק לפעולה בטוחה/אידמפוטנטית, עם backoff ו־jitter.
  • DB transaction קצרה סביב invariant עסקי.
  • Connection pool מוגבל; יותר connections אינם תמיד יותר throughput.
  • Graceful shutdown: הפסק לקבל עבודה, סיים inflight וסגור resources.
  • Health/readiness checks, metrics ו־distributed tracing.
  • נעילת dependencies, scanning ועדכוני אבטחה.
  • Formatter/linter/type-check/tests כחלק מ־CI.
